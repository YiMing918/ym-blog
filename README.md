## 特点：功能全清单

### ✍️ 写文章（后台 `/admin`，手机优先）

- **Markdown 编辑 + 实时预览**：预览由服务端同一个渲染器生成，和发布后的样子完全一致，不会出现「预览好好的、发出来变样」。
- **三层防丢稿**：浏览器本地自动保存 → 服务端自动保存（每人每篇一份，绝不覆盖已发布正文）→ 切后台/关页面时强制再存一次。写一半断电、误关页面，回来能接着写。
- **文章状态机**：草稿（Draft）/ 定时发布（Scheduled）/ 已发布（Published）/ 仅自己可见（Private）/ 回收站（Trash），回收站保留 30 天可还原，超时才真删。
- **定时发布不用等任务**：公开列表按「发布时间到了没有」实时判断，到点自动出现，零延迟零故障点。
- **历史版本**：发布和手动保存都会留一版，一键还原旧稿；还原前会先把当前内容再存一版，反悔也能再反悔。每篇保留最近 20 版。
- **发布面板**：自定义短链（Slug，短链接名）、标签、封面、摘要、置顶、单篇关评论、文章密码（设了密码的文章访客要输密码才能看）一处配齐。
- **模板克隆**：拿一篇旧文当模板新建，版式和写法直接复用。
- **草稿预览链接**：生成带随机口令的链接，发给朋友先看草稿；可过期、可撤销，不会被搜索引擎收录。
- **AI 写作助手（可选，自备 Key）**：接任意 OpenAI 兼容服务（OpenAI / DeepSeek / 各类中转），编辑器里一键「AI 生成摘要」「AI 生成正文」。配置在后台「站点设置 → AI 写作」（服务地址、模型、温度、两套提示词）；密钥只存服务端、页面只显示配没配，永不下发。没配置时按钮会明确提示去哪儿填，不会静默失败。（思路借鉴 EdgeBlog，见版本历史 v1.1.0）

### 🖼 发图与视频（不经过服务器中转）

- **粘贴 / 拖拽 / 多选直传**：图片和视频由浏览器拿「预签名地址（Presigned URL）」直传进 R2 存储桶，**文件字节不经过 Worker（边缘函数）**——这是铁律：免费版函数扛不了大文件流量，直传又快又不烧额度。
- **媒体库**：网格管理全部附件；可改显示名、分组（相册 Album）；删文件前会先数引用——正被文章用着的会拦下来并列出是哪几篇，防误删把文章图弄没。
- **媒体回收站**：删错了先进回收站，能还原；30 天后清理任务才真删存储对象。
- **视频两种来源**：本地视频直传后用站点自己的播放器播（存储桶绑了自定义域名，原生支持拖动进度）；B 站 / YouTube 只贴链接，正文单独一行就会变官方播放器。
- **组图排版约定**：一个段落里放 1 张图 = 单图大图；2 张 = 双列；3 张 = 一大多小；4 张以上 = 图集条；图片说明里加 `|长图` 后缀 = 超长截图限高展示、点开看全图。
- **大小上限（后台可调）**：图片 20MB / 视频 200MB / 文件 50MB。超大视频会提示改贴外链——外链零存储、播放更流畅，本地直传留给短视频和私密视频。
- **封面兜底**：没单独设封面时，自动取正文第一张图当封面。

### 👀 访客看的页面（服务端直出 HTML）

- **打开快**：文章正文在发布时就预渲染好存着，访客打开是直出成品页面，不等浏览器现场拼——手机弱网、微信里打开都快，分享到微信 / QQ 能带出标题和摘要。
- **阅读体验**：文章目录（TOC）可折叠、阅读进度条、代码块带复制按钮和语言标注、图片灯箱（Lightbox）点开大图可左右翻、字数与预计阅读时长、太久没更新的文章有过期提醒。
- **深色模式三段式**：跟随系统 / 固定浅色 / 固定深色，后台设置里选，默认跟随系统。
- **首页组成**：置顶 + 文章列表（卡片或紧凑列表，后台可换）、说说最新几条、那年今日（On This Day）、热门 Top 5、搜索框。
- **齐全的栏目页**：归档（按年月时间线）、标签云与标签页、说说页、友链页、关于页（就是一篇特殊文章，在后台当普通文章改）。
- **全文搜索（FTS5 + trigram）**：正文与标题建全文索引，中文按 3 字片段切分——搜任意子串都能命中并按相关度排序，不再全表扫描；两个字的短词、索引未建等情况自动退回子串匹配兜底，行为只升不降。（做法借鉴 EdgeBlog）
- **相关文章 / 上下篇**：按共同标签数自动算，不用手动维护。

### 💬 评论（自带，不挂第三方）

- **本体评论**：数据在你自己的数据库里，不依赖任何外挂评论服务（外挂哪天关停，评论不会跟着没）。
- **先审后显**：新评论默认进待审队列，后台一键通过 / 驳回 / 标垃圾 / 删除 / 回复；站长回复带身份标记。
- **老访客免审**：曾经有评论被通过过的访客，新评论可直接显示（后台可配）；含链接多的评论自动进待审。
- **防刷内置**：按 IP 频率限制（后台三档可调）、可选人机验证（Turnstile，默认关，需要时开）、评论内容一律净化转义——评论区是最常见的被黑入口，这里按最严口径处理。

### 🔐 登录与账号安全

- **账号密码登录**：单站长账号；密码只存哈希（scrypt，参数见维修手册），还加了服务端「胡椒」（Pepper，存在环境变量里、不进数据库，库被拖走也撞不开密码）。
- **登录保护**：连续失败 5 次锁定 15 分钟、再犯指数退避；错误提示恒为「账号或密码错误」，不给试探口子。
- **会话管理**：会话令牌只存哈希；能看全部登录设备、一键下线全部；改密码会自动踢掉所有设备。
- **恢复码（第一层恢复）**：后台生成 10 个一次性恢复码（只显示一次），忘密码时在登录页用任意一个码直接重置；改密后旧码全废、重新生成。
- **终极重置（第三层恢复）**：恢复码也丢了，进 Cloudflare 后台对数据库跑一句 SQL，就能回到「初始化站长」流程重设账号——完整步骤在 [MAINTENANCE.md](MAINTENANCE.md)，不依赖任何人。

### ⚙️ 站点设置（后台表单，不碰代码）

站名、介绍、头像、首页大标题与介绍文、主题色（Accent，另有 6 套配色预设一键换）、首页布局（卡片 / 列表）、文章宽度、深色策略、每页篇数、回收站天数、上传上限——全部在后台填表点选，**保存即时生效**，不用重新部署。开关组逐项都写了「关掉会怎样」：搜索、评论、评论审核、RSS（订阅源）、限流档位、人机验证、友链朋友圈抓取。AI 写作的配置也在这一页单独成卡（见「写文章」节）。

### 📊 统计与用量（心里有数）

- 浏览计数**按天聚合**：一篇文章一天只占一行数据，既不烧数据库每日额度、也不拖慢正文读写。
- 后台统计页：总阅读、近 30 天热门榜、**逐日访问量（PV）序列 + 评论趋势**、媒体用量（按图片 / 视频 / 文件分段）、内容计数、最近备份时间。

### 🧳 备份与逃生（数据永远是你的）

- **每周双通道自动备份**：通道一按表导出 JSON 存进私有备份桶（保留 12 期，带对账计数）；通道二逐表导出整库 SQL 存进 GitHub（保留 90 天），互为备份。
- **一键逃生包**：随时把全部文章导成 Markdown 文件包（带 front-matter 文件头元信息）+ 附件清单 + 评论与设置 JSON——哪天想搬去 Hugo / Astro / WordPress，原文直接能用，Cloudflare 只是托管方不是牢笼。
- **整站导入恢复**：导入前会**自动先备份当前站**，再按表导入并给出对账报告；短链冲突会自动改名并留跳转，旧链接不断。

### 🐕 全自动运维（部署完就不用管）

- **推送即部署**：代码推到 GitHub 自动上线。
- **看门狗（Watchdog）**：每天巡检首页、RSS 与健康端点，异常先复查一遍（抖动不误报），真有问题开 Issue 留痕；全好静默。
- **友链探活**：每 20 分钟自动查一遍友链还通不通，连续失败的自动在前台置灰、后台标红。
- **每日清理**：超期回收站、过期会话、没传完的半成品记录自动清。
- **心跳保活**：超过 25 天没提交自动留一个时间戳提交，防止 GitHub 把长期不活动的定时任务停掉。

## 详情说明

**架构一句话**：访客页面和接口都由 Pages Functions（边缘函数）在请求时处理，文章存 D1（SQLite 数据库），图片视频存 R2（对象存储），一切重活（渲染、打包、统计）都挪到「发布时 / 定时任务时」做，访客读页面这条路上只做最少的事——所以快、所以省额度。

**为什么免费够用**（以官方免费额度为准，个人小站量级）：数据库每天可读 500 万行 / 写 10 万行，浏览计数按天聚合后一天一文只写一行；存储桶免费 10GB 且下载流量免费；函数每天 10 万次请求。唯一要留神的：免费额度是「超了就停到第二天早上 8 点」而不是降速，所以本站在索引、缓存、限流上都按省着用的口径设计，并留了「升到 5 美元付费版问题全消失」的预案（见维修手册）。

**数据在哪**：文章、评论、设置在你的 D1 里；图片视频在你的媒体桶里；备份在你的私有备份桶 + GitHub 里。三样都在**你自己**的账号下，不经过任何第三方。

## 部署方法（图文步骤）

全程在浏览器里点，不用装任何软件。示例域名统一写 `blog.example.com`（你的博客域名）和 `media.example.com`（媒体域名，一般是博客域名的子域名，如 `media.blog.example.com`），照着换成你自己的即可。预计 20–30 分钟。

### 第 0 步：准备两个账号

- 一个 **GitHub** 账号（放代码）、一个 **Cloudflare** 账号（放站点）。都没有就先各自注册，都是免费的。

### 第 1 步：把仓库拿下来（Fork / 建仓）

1. 打开本仓库页面，点右上角 **Fork**（复刻）→ 选你自己的账号 → Create fork。这样你得到一份属于你的代码副本，以后改代码、推送部署都在你这份里做。
2. （可选）也可以点 **Use this template / 新建仓库** 后把本仓库文件整包上传，效果一样。

### 第 2 步：建数据库 D1

![D1 数据库后台](https://gcore.jsdelivr.net/gh/YiMing918/ym-blog@main/docs/cf-d1.png)
*建好后的 D1 数据库页（真实后台截图，演示数据）：表建好后能在这里逐张核对，执行初始化脚本也在这个控制台里粘贴运行。*

1. 登录 Cloudflare 后台 → 左侧 **Storage & Databases（存储与数据库）→ D1 SQL Database** → **Create（创建）**，名字填 `ym-blog-db`，创建。
2. 点进这个库 → **Console（控制台）** 页签 → 把仓库里 `schema/0001_init.sql` 的**全部内容**粘贴进去 → Execute（执行）。看到共 21 张表建好就是对的。
3. 再把 `schema/0002_seed.sql` 同样粘贴执行一次（这是初始设置和示例文章）。
4. 最后把 `schema/0003_fts.sql` 粘贴执行一次（全文搜索索引；**已在跑的旧站升级到 v1.1.0 时只需补这一步**，执行完刷新搜索即生效，不用动其他表）。
5. 再把 `schema/0004_media_trash.sql` 粘贴执行一次（媒体回收站保留期用的时间戳列；**已在跑的旧站升级到 v1.1.2 时只需补这一步，且必须先执行它、再部署新代码**，顺序反了媒体删除/还原会报错；执行前先确认 `media` 表还没有 `trashed_at` 列，这条加列语句不能重复执行）。
6. 回到这个库的详情页，记下 **Database ID（数据库 ID）**，第 6 步要用。

### 第 3 步：建两个存储桶 R2

![R2 存储桶后台](https://gcore.jsdelivr.net/gh/YiMing918/ym-blog@main/docs/cf-r2.png)
*R2 桶列表（真实后台截图）：媒体桶与备份桶两个分开建；媒体桶还要绑一个自定义域名，图片视频才能公开访问。*

1. 左侧 **R2 Object Storage（R2 对象存储）** → 若从没开过，会让你先绑一张银行卡开通（免费额度内不扣费，超了才按量；这一步过不去后面建不了桶）。
2. **Create bucket（创建桶）** → 名字 `ym-blog-media`（媒体桶，存图片视频）→ 创建。
3. 再建一个 `ym-blog-backups`（备份桶，存自动备份，**不要绑任何公开域名**）。
4. 给媒体桶绑域名：点进 `ym-blog-media` → **Settings（设置）→ Custom Domains（自定义域名）→ Connect Domain** → 填 `media.example.com`（换成你的媒体域名）→ 确认。状态变 Active（生效）后，图片视频就从这个域名公开访问。
   - ⚠️ 不要图省事用桶自带的 `r2.dev` 域名当生产地址：官方对它限流，会随机 429 报错。
5. 给「预签名直传」配两样：
   - **CORS（跨域）**：媒体桶 Settings → CORS Policy → 加一条：Allowed Origins（允许来源）填你的博客域名 `https://blog.example.com`，Allowed Methods 勾 `PUT` 和 `GET`，保存。
   - **S3 凭据**：R2 总览页 → **Manage R2 API Tokens（管理 API 令牌）** → Create API Token → 权限选 **Object Read & Write（对象读写）**、只限 `ym-blog-media` 桶 → 创建后把 **Access Key ID** 和 **Secret Access Key** 抄下来（只显示一次），第 6 步要用（方式 B 的人在第 5 步填）。
   - 顺带记下 R2 总览页显示的 **Account ID（账号 ID）**：S3 端点就是 `https://<账号ID>.r2.cloudflarestorage.com`。

### 第 4 步：站点项目不用预建，配置值先想好放哪

1. **Pages 项目不用手动建**：走第 6 步方式 A 的话，部署流水线第一次运行时会由 wrangler 自动把 `ym-blog` 项目建出来，你什么都不用点。
   - ⚠️ 一个实测踩过的坑：流水线是「先灌密钥、再部署」的顺序。万一日志里在灌密钥一步报 `Project does not exist`（项目还没建出来，密钥没地方灌），先去 Cloudflare 后台用 **Workers & Pages → Create → Pages → Connect to Git** 选你的仓库、建出一个空项目壳；**建完立刻在该项目的 Settings 里关掉 Git 自动部署**（本方案的正式部署只走 GitHub Actions，两条路都开着会互相覆盖），然后回 GitHub 重跑一次 `deploy` 工作流即可。
2. **仓库里的 `wrangler.toml` 只放占位值，不要改它**：数据库 ID、媒体域名、S3 端点这三处真值，方式 A 由流水线在部署时从 GitHub Secrets 自动替换进去（见第 6 步与配置表）；桶名两处若改了名，才需要同步改文件里的 `bucket_name` 与 Pages 普通变量 `R2_S3_BUCKET`（在 wrangler.toml / Pages 设置里，不是密钥）。
3. 只有走第 6 步**方式 B**（Pages 连 Git）的人才需要手动改 `wrangler.toml` 的三处占位（`database_id` / `MEDIA_PUBLIC_BASE` / `R2_S3_ENDPOINT`，换法同上），并照第 5 步手动配 Pages 变量。

### 第 5 步：配密钥（Pages 环境变量 / Secret）——方式 A 可跳过本步

- **走方式 A（推荐）的人跳过本步**：第 6 步把同一批值填进 GitHub Secrets 后，部署流水线会自动把运行时密钥逐个灌进 Pages 的加密变量，两边不要重复手工配。
- **走方式 B 的人手动配**：Cloudflare 后台 → **Workers & Pages → ym-blog → Settings（设置）→ Environment variables（环境变量）**，按下面 [配置表](#配置表环境变量与密钥) 逐个添加，标「Secret（加密）」的添加时选 **Encrypt（加密）**。
- 不管哪种方式，这几项必填先想好值：`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`（第 3 步抄下的）、`PASSWORD_PEPPER`（自己编一串至少 32 位的随机字符，**记牢、别再改**——改了所有旧密码都验不过）、`TASK_SECRET`（同样自编一串随机字符，GitHub 与站点两边填同一个值）。

### 第 6 步：部署上线（两种方式选一种）

**方式 A · 推送自动部署（推荐，之后改代码推一下就上线）**

1. GitHub 仓库 → **Settings → Secrets and variables → Actions** → New repository secret，把 [配置表](#配置表环境变量与密钥) 里「GitHub 仓库 Secrets」一节的 **12 项**逐个配齐。其中部署令牌 `CLOUDFLARE_API_TOKEN` 在 Cloudflare 后台 **My Profile → API Tokens** 里用「编辑 Cloudflare Workers」模板建，再补上 D1、R2、Pages 的编辑权限。
2. 一次 `deploy` 运行会连做三件事：用 Secrets 里的真值替换 `wrangler.toml` 的占位（只在运行器内存里，不回写仓库）→ 把运行时密钥灌进 Pages 加密变量（等同于替你做了第 5 步）→ 部署上线。所以第 4、5 步对方式 A 都是「看懂即可、不用动手」。
3. 随便改一个文件提交（或到 **Actions** 页手动 Run 一次 `deploy`）→ 等绿勾 → 打开部署日志里给出的 `https://<你的项目名>.pages.dev` 就是你的站了。

**方式 B · Pages 连 Git（Cloudflare 官方托管构建）**

1. Cloudflare 后台 → **Workers & Pages → Create → Pages → Connect to Git** → 选你 Fork 的仓库。
2. 构建设置：Framework preset（框架预设）选 **None**，Build command（构建命令）**留空**，Build output directory（输出目录）填 `.`（根目录）。
3. Save and Deploy，等第一次部署完成。

### 第 7 步：初始化站长与恢复码（最重要，别跳）

1. 打开 `https://<你的站点>/admin`，会进入「初始化站长」页：设**用户名 + 密码**（至少 8 位）→ 创建。
2. 页面会给出 **10 个恢复码，只显示这一次**——立刻抄下来或截图，存进密码管理器 / 纸质本子。这是将来忘密码时自救的第一层钥匙。
3. 本方案的建号只走上面这条页面初始化路：**不要用环境变量预置站长密码**（不配、也不要配 `INITIAL_ADMIN_PASSWORD` 这类变量），账号密码只在你初始化那一刻由你亲手设定、只存哈希。

### 第 8 步：绑你自己的域名

1. 前提：你的域名 DNS 已托管在 Cloudflare（域名在本账号下）。
2. **Workers & Pages → ym-blog → Custom domains（自定义域名）→ Set up a custom domain** → 填 `blog.example.com`（换成你的）→ 按提示确认，证书会自动签发。
3. 生效后把 GitHub Secret 里的 `SITE_URL` 改成这个正式域名（看门狗 / 探活 / 清理 / 备份四个任务工作流都调它，填错了它们会去敲旧地址）。若想让 RSS / sitemap 固定用正式域名拼绝对链接，再去 Pages 后台手动加一个普通变量 `SITE_BASE_URL`、填同一个地址即可（部署流水线不会自动灌这个变量；不加也行，站点会按访客实际访问的域名推导）；媒体域名同理在第 3 步已绑定。

### 第 9 步：上线后自查清单

- [ ] 首页能打开、示例文章在；把站名/介绍在后台「站点设置」改成自己的。
- [ ] 后台发一篇测试文章，插一张图、传一个小视频，发布后前台能看、图能点大、视频能播。
- [ ] 用没登录的浏览器给文章留一条评论，确认它先进了后台待审队列，你通过后才出现。
- [ ] 后台「备份」页点一次「立即备份」，确认备份列表里多了一条、能下载。
- [ ] 「备份与数据」里点一次「导出 Markdown 逃生包」，确认能下载 zip。
- [ ] 删掉示例文章和示例说说（会先进回收站，正常）。

### GitHub 仓库 Secrets（Actions 用，共 12 项）

这是本方案实际在用的全清单。`deploy` 流水线每次运行时，会用其中的真值替换 `wrangler.toml` 占位、并把运行时密钥灌进 Pages 加密变量——所以这 12 项是唯一的「真值存放处」，除 GitHub 加密库与 Pages 生产环境外，真值不要出现在任何其他地方（包括仓库文件与聊天记录）。

| Secret | 用途 |
|---|---|
| `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` | 部署用；没配则自动部署整条跳过（用 Pages 连 Git 部署的人不需要） |
| `D1_DATABASE_ID` | 第 2 步记下的数据库 ID，部署时替换 `wrangler.toml` 的占位 ID；backup 通道二逐表导出也用它定位库（与 deploy 共用） |
| `D1_EXPORT_TOKEN` | 备份通道二专用令牌（Cloudflare 后台 → My Profile → API Tokens 建自定义令牌，只给 `Account · D1 · Read` 权限即可），与部署令牌分开、不混用；没配则通道二自动跳过，通道一不受影响 |
| `MEDIA_PUBLIC_BASE` | 媒体公开域名（如 `https://media.example.com`），部署时替换占位 |
| `R2_S3_ENDPOINT` | `https://<账号ID>.r2.cloudflarestorage.com`，部署时替换占位；不配则按账号 ID 自动拼 |
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | 运行时密钥，部署时灌进 Pages（直传必需） |

| `TASK_SECRET` | 双职：既是任务接口的通行证（看门狗/探活/清理/备份都调它），也由流水线灌进 Pages，两边天然同值 |

## 常见问题 FAQ

**Q：真的完全免费吗？**
A：个人小站量级在免费额度内是真免费。唯一的开通动作：用 R2 前 Cloudflare 要你绑一张卡（免费额度内不扣费）。将来量真的大到顶了，升 Workers Paid（付费版，5 美元/月）后额度问题基本全消失，本站设计时已把这条路留好。

**Q：手机上能完成全部操作吗？**
A：能。后台就是按手机优先做的：写文章、传图传视频、审评论、改设置、看统计、跑备份，都在手机浏览器里点完。电脑上只是屏幕更宽，没有「电脑专属功能」。

**Q：忘了后台密码怎么办？**
A：三层自救，都不用求人：①登录页用恢复码重置（初始化站长时让你存的那 10 个码）；②恢复码也丢了——第二层（任务密钥开窗口）本版未实现，跳到③；③进 Cloudflare 后台按 [MAINTENANCE.md](MAINTENANCE.md) 的「终极重置」对数据库跑一句 SQL，重新初始化站长。详见维修手册。

**Q：图片视频传不上去？**
A：先看报错：提示超上限就是文件太大（视频可改贴外链）；提示类型不支持是格式不在白名单；一直转圈多半是媒体桶的 CORS 没配或配错（照部署第 3 步重配）。还不行看维修手册故障对照表。

**Q：评论提交了却不显示？**
A：默认先审后显——去后台「评论管理」的待审队列里通过它。若你不想审，在设置里关掉「评论审核」。

**Q：我的文章和数据到底存在哪、安不安全？**
A：全在**你自己**的 Cloudflare 账号里（D1 数据库 + R2 桶），代码仓库只放程序不放数据。公开仓库里永远不要提交密钥、Database ID 等任何敏感信息（仓库里只放占位值）；部署示例里的域名都是占位示例。

**Q：想搬家怎么办？**
A：后台一键导出 Markdown 逃生包（文章原文 + 附件清单）或整站 JSON；图片视频本体在你的媒体桶里可整桶下载。天要下雨站要搬家，数据随时能走。

**Q：示例文章、示例说说怎么删？**
A：后台文章列表里删除即可（进回收站，30 天内可还原）；说说在「说说管理」里删。

## 隐私说明

- **访客侧**：本站不接任何第三方统计、不种广告 Cookie。评论者填的联系方式只存哈希与掩码，不明文落库；评论者 IP 只存加盐哈希，用于限流与防刷，不存明文 IP、不做画像。
- **浏览计数**：只有「哪篇文章哪天被看了几次」的聚合数字，没有访客级记录。
- **站长侧**：密码只存哈希 + 服务端胡椒；会话令牌只存哈希；恢复码只存哈希。真秘密（R2 密钥、任务密钥、胡椒）只存在 Cloudflare 环境变量里，**不进仓库、不进数据库**。
- **部署者注意**：Fork 后先把 `wrangler.toml` 里的示例值换成你自己的；仓库里出现的域名（`blog.example.com`、`media.example.com`）全是占位示例，不是任何人的真实站点。

## 已知边界（诚实清单）

- **Passkey（通行密钥 / 指纹登录）只是预留**：数据库表和接口路径已留好，本版返回「未启用」，登录仍以账密 + 恢复码为准。将来启用后可绕开慢哈希问题，是计划中的正解，但现在别指望它。
- **分片上传（Multipart）未做**：接口位已留、调用返回「未启用」。200MB 以内的视频走普通直传没问题；更大的文件请贴 B 站/YouTube 外链，或先压缩再传。
- **友链朋友圈抓取默认关且未实现聚合**：友链探活（查对方站点通不通）是真功能；「把友链最新文章抓过来聚合展示」只有开关和缓存表，抓取逻辑未做，开了也不会有数据，别开。
- **文章密码的哈希强度与登录同级**：为照顾免费版函数的算力上限用了折中参数；文章密码只当「熟人之间的小锁」，别拿它保护高敏感内容。
- **OG 分享图不自动生成**：文章页有标题/摘要的分享 meta，但没有逐篇自动生成的 og:image 大图；分享卡片显示以各平台抓取为准。
- **缩略图未接 Cloudflare 图片变换**：列表与封面用原图 + CSS 裁切显示，图特别多时首屏会稍重；这是可选项优化，未做不影响使用。
- **备份通道二（逐表导出的整库 SQL）是整库级恢复手段**：日常恢复优先用站内导入（按表 JSON）；整库 SQL 恢复步骤在维修手册里（产物文件头也写了恢复法），操作前先备份现状。
- **全文索引与官方整库导出互斥（平台限制），通道二已绕开**：自 v1.1.0 起库里有 FTS5 虚拟表，Cloudflare 官方整库导出会被服务端永久拒绝（cannot export databases with virtual tables）；通道二自 v1.1.3 起固定改走逐表 SQL 导出——结构解析自仓库 `schema/` 迁移文件（经 D1 HTTP API 自省表结构会被引擎授权器以 SQLITE_AUTH 拒绝，所以不向库问结构），数据逐表拼成整库 SQL 存 GitHub 90 天，恢复时执行产物 SQL 即可、文件末尾自带 FTS rebuild。通道一按表备份不含可重建的索引表，恢复后同样靠 rebuild 重建索引。**双通道均为真备份，不再有降级跳过**（始末见版本历史 v1.1.3）。
- **AI 写作只做管道**：本站不内置任何 AI 账号与额度，要用得自备 OpenAI 兼容服务的 Key；没配就等于没这功能，不影响其他任何功能。
- **第二层恢复（任务密钥开改密窗口）未实现**：忘密码时用第一层（恢复码）或第三层（终极重置），两层都在维修手册里写了全步骤。
- **静态资源靠根目录 `_routes.json` 直出，别删**：`/assets/*`（前台样式与脚本）与 `/admin/*`（后台三件套）是纯静态文件，靠 `_routes.json` 把它们排除出函数调用、由 Pages 静态层直出；其余路径（含全部 `/api/*` 与页面 SSR）仍走函数。这个文件必须躺在部署根目录并随部署包一起上线——删了它、或部署时没带上它，首页还能开（函数 SSR 正常），但样式、脚本和整个后台页面会全部 404。排查口诀见维修手册故障对照表。

### v1.1.3（2026-11-10）· 备份双通道补完（通道二从「从未真跑」到真产物落地）

- **先给通道一平反：完整，「篇数对不上」是时间差、不是丢数据**：把当时最新一份周备真正下载下来逐表点数、再与数据库逐篇对账——那份备份导出于周一早上，文件里的 8 篇正是导出时刻存在的全部文章（关于页 + 7 篇），当天上午才新建的文章不在里面理所当然；双向差集为空、登记的对账计数与文件实数逐项吻合，同一天傍晚的另一份备份交叉验证同样自洽。代码层确认导出是对每张表整表 `SELECT *`、无过滤无行数上限；刻意不进备份的只有会话、限流、恢复码等可重建/敏感的运行态表与 FTS 索引表（恢复后 rebuild），属设计。
- **通道二为什么自上线起从未产出（三段根因，逐个实测钉死）**：① `wrangler.toml` 里的数据库 ID 一直是占位值，工作流识别到占位便静默跳过，从未真跑——这是它「看起来在备份、其实从没备份过」的直接原因；② 就算把 ID 填成真值，官方 `wrangler d1 export` 对含 FTS5 虚拟表的库会被平台**永久**拒绝（Cloudflare 官方 Known limitations 明列：含虚拟表的库不支持导出，变通只有删表，对生产库不可接受），且 wrangler 对只给 D1 读权限的令牌过不了它自己的鉴权（2026-11-10 实测 Authentication error code 10000）；③ 改走 D1 HTTP API 逐表导出后，第一句查表结构的 `SELECT … FROM sqlite_master`（`PRAGMA table_info` 同属此类）被 D1 引擎授权器以 `SQLITE_AUTH` 拒绝——两把权限完全不同的令牌撞出逐字相同的错，证明与令牌无关、是语句级限制（Cloudflare 社区 2026-10 有同案报告）。
- **最终路线（已生产跑通）**：`backup.yml` 通道二固定走新增的 `scripts/d1-dump.mjs` 逐表导出——结构解析自仓库 `schema/` 迁移文件（迁移是建库的唯一来源，结构上不会漂移；解析不了的语句直接报错终止、绝不静默漏表；每张非空表导出前先探一行核对列集，迁移之外的手工改列当场点名），数据经 D1 HTTP API 以显式列名逐表拼成整库 SQL，FTS 只出建表语句、产物末尾自带 rebuild；令牌换成专用只读的 `D1_EXPORT_TOKEN`（`Account · D1 · Read`，与部署令牌分开，仓库 Secrets 由 11 项变 12 项）。另把两个 job 改为串行：首跑时两 job 并行，官方导出尝试占用 D1 的窗口里通道一的站内备份吃了一次 500（导出期间会阻塞该库其他请求，平台已知限制），串行后互不干扰、通道一失败时通道二照常跑，通道一调用另加自动重试。
- **账面小修**：备份登记的 `size_bytes` 此前记的是 JSON 字符串长度而非真字节数（中文内容下约差一倍），自动/手动备份与导入前自动备份两处登记已统一改为 UTF-8 字节数；冒烟新增 1 项断言（登记值须与桶内对象字节数一致），共 167 项全过。
- **升级方法**：同步 `.github/workflows/backup.yml` 与新增的 `scripts/d1-dump.mjs`，在 Cloudflare 后台建一枚自定义令牌（`Account · D1 · Read`）存为仓库 Secret `D1_EXPORT_TOKEN`，再手动触发一次 backup，看到双 job 全绿、产物 `d1-export` 出现即成；站内代码除 size_bytes 修正外无行为变化。2026-11-10 本站生产实测：通道一新登记一期（23 篇文章 / 110 附件 / 56 评论 / 7 动态），通道二首份真产物落地（21 张表共 974 行，SQL 约 5.9 MB）。

## Fork 部署与原站的区别

代码与原站一模一样，但博客里的文章、图片、账号和自动化，全在作者自己的 Cloudflare 账号里；Fork 只能把代码带走，带不走作者的数据和配好的服务。差多少、怎么补，一条一条列清楚：

1. **文章不在仓库里，Fork 后是空博客**：全部文章、评论、说说和站点配置都存在作者自己的 D1 数据库 `ym-blog-db` 里，仓库里只有建表脚本 `schema/0001_init.sql`。按部署步骤跑完种子脚本 `schema/0002_seed.sql`，站里也只有 1 篇示例文章（另有 1 篇关于页、1 条示例说说，检查清单里本来就要求删掉），作者的文章一篇也不会跟着 Fork 走；想有内容，只能自己写。

2. **管理员账号密码要自己设**：仓库和部署里没有作者的管理员账号密码；首次打开自己站的 `/admin`，按提示设一个用户名和至少 8 位的密码，系统会给 10 个一次性恢复码，只显示一次，务必保存好。不要用 `INITIAL_ADMIN_PASSWORD` 环境变量预设管理员密码（这是高危做法，首次登录后必须清理）。

3. **媒体文件在作者的 R2 里**：文章里的图片、视频存在作者自己的 R2 存储桶（媒体桶 `ym-blog-media`，存储桶绑了自定义域名；备份桶 `ym-blog-backups`），不在仓库里。Fork 后要自己建桶、绑域名，再按部署步骤配好；原站的图片、视频一张也不会出现在你的站里。

4. **AI 写作要填自己的密钥**：AI 写作助手可选、自备 Key，接任意 OpenAI 兼容服务（OpenAI / DeepSeek / 各类中转），在自己站后台「站点设置 → AI 写作」里填服务地址、API Key、模型、温度和两套提示词；不填就没有这个功能。密钥只存服务端，页面只显示是否已配置，永远不下发。

5. **自动化要自己配**：部署、看门狗、友链探活、每日清理、每周备份、心跳保活这些工作流都在 `.github/workflows/` 里，代码会跟着 Fork 走，但 GitHub 的安全规则让它们不能直接用：Fork 后 Actions 默认是关闭的，定时任务默认不跑；12 个 GitHub Secrets（`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`、`D1_DATABASE_ID`、`D1_EXPORT_TOKEN`、`MEDIA_PUBLIC_BASE`、`R2_S3_ENDPOINT`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`、`PASSWORD_PEPPER`、`TASK_SECRET`、`INITIAL_ADMIN_USERNAME`、`SITE_URL`）不会跟着 Fork 复制。补齐办法：去自己仓库的 Actions 页手动启用一次工作流，再按「配置表」把 12 个 Secrets 和 Cloudflare 侧的 D1 / R2 / Pages 绑定配好；看门狗和友链探活还要在自己站里填好 `SITE_URL` 与 `TASK_SECRET` 才能跑起来。

6. **代码里的功能，Fork 后全都有**：Markdown 编辑 + 实时预览、三层防丢稿、文章状态机与回收站（30 天）、历史版本（最近 20 版）、全文搜索（FTS5 + trigram）、深色模式三段式、6 套预设配色（活力橙 / 海洋蓝 / 葡萄紫 / 森系绿 / 湖水青 / 玫红）、媒体库与媒体回收站、评论先审后显与防刷、友链探活、说说、归档 / 标签 / 关于页——这些全在代码里，部署好即有，不用另配。

补齐「自己的 D1 + R2 + 12 个 Secrets + 手动启用一次 Actions」后，你的站和原站在功能上完全一致；差别只剩内容：文章、图片、评论和日常巡检，都是你自己的了。原站的文章和媒体、作者的 Cloudflare 账号与域名绑定，永远无法复制——这是设计使然：数据只能存在自己的账号里。

**Q：Fork 后直接部署就能用吗？**

A：能打开、能注册管理员、能写文章，但站里没有作者的文章和图片，自动化也没启用；先按「部署方法」走完（含第 9 步的 6 项自查清单），再把 Secrets 和 Actions 配好，才算真正可用。

**Q：能把原站的文章搬到我的 Fork 站上吗？**

A：不能一键搬。文章在作者的 D1 里，不在仓库里，也没有现成的导出文件跟着 Fork 走；只能一篇篇自己复制重发，图片要重新传进自己的 R2。

**Q：为什么 Fork 后 Actions 不自动跑？**

A：这是 GitHub 的安全规则：Fork 的仓库里 Actions 默认关闭，定时任务默认不跑，Secrets 也不复制——防止别人 Fork 一个仓库就能用原作者的密钥和额度。所以必须先手动启用一次工作流，补齐自己的 Secrets，它才会按定时自动跑。
