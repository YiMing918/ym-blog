# YM 博客 · 融合版

一个**带完整网页后台的真·动态博客**，全部跑在 Cloudflare 免费额度里：不用租服务器、不用数据库主机、不用备案。手机、平板、电脑打开后台就能写文章、传图、传视频、改站名和颜色，像用 App 一样点点点。适合个人小站，也按通用产品标准做了额度保护与防刷——别人拿去部署、人多了同样扛得住。

> **这版是怎么来的**：把几条成熟路线的长处缝在了一起——动态博客（WordPress/Typecho 那类）的防丢稿、回收站、版本回滚；新兴 CF 原生博客的边缘架构与友链探活；静态博客的轻快与耐用；再补上自研的账密登录、恢复码、看门狗与一键逃生导出。设计细节与取舍都在 [MAINTENANCE.md](MAINTENANCE.md) 与仓库内的设计说明里。

## 先选下载文件

部署有三种方式（见「部署总览」），先对着表看你走哪种、要下哪个文件：

| 部署方式 | 下载哪个文件 | 怎么用 |
|---|---|---|
| 方式一 · GitHub 连接自动部署（推荐） | 不用下文件 | 在 GitHub 上 Fork 本仓库，部署全程在网页里点，具体见「方式一」一节 |
| 方式二 · 手机部署包 | 发行版（Releases）里的 `ym-blog-worker-deploy-*.zip`（带 `-worker-` 的**直传专用包**） | 在 Cloudflare 控制台的 Pages 里「上传资产」整包上传，新建项目即上线；同页的 `SHA256SUMS.txt` 是校验文件，用来核对 zip 有没有下完整、下对版。**别下成不带 `-worker-` 的普通包直传**——普通包里的 `functions/` 文件夹拖拽上传不会被编译，本站全部页面都靠后端出，传了必然连首页都是 404（原因见方式二） |
| （参考）普通部署包 | 发行版里的 `ym-blog-deploy-*.zip` | 是 `functions/` 结构的成品包，给 Git 连接 / wrangler 部署和仓库灾难恢复用，**不用于控制台直传** |
| 方式三 · wrangler 命令行 | 本仓库源码（GitHub 页面点 Code → Download ZIP，或用 git 克隆） | 在电脑上解压，照「方式三」一节用命令行部署 |

⚠️ **注意**：发行版页面里 GitHub 自动生成的 **Source code（zip / tar.gz）是整个仓库的源码快照，不能直接当 Pages 部署包上传**（里面混着文档、脚本和测试文件，目录结构也不是部署根）。部署包请认准文件名带 `deploy` 的那个 zip。

## 新手先看这里

**这篇文档假设你完全没用过 Cloudflare 和 GitHub。** 部署一共要先准备三样东西，逐项说清是什么、去哪弄、多少钱；后面的步骤里第一次出现的术语都会用括号讲一句人话。

### 要准备的三样东西

| 准备什么 | 是什么（人话） | 去哪弄 | 多少钱 |
|---|---|---|---|
| Cloudflare 账号 | 你的博客最终就跑在这家公司的免费服务器上，数据库、存图片的地方也都在你这个账号里 | 打开 [dash.cloudflare.com](https://dash.cloudflare.com) → 点注册（Sign up），用邮箱注册即可 | 免费。本项目用到的功能都在免费额度里；只有「开通 R2 存储」这一步会让你先绑一张银行卡（免费额度内不扣费，超量才扣，个人博客基本超不了） |
| GitHub 账号 | 放代码的网站。代码放在这里，Cloudflare 从这里取代码上线；自动备份、自动巡检也靠它定时跑 | 打开 [github.com](https://github.com) → 点 Sign up 注册 | 免费 |
| 一个你自己的域名 | 博客的门牌号，如 `blog.example.com` 文中只是示例，你换成自己的。没有域名也能先用 Cloudflare 送的 `*.pages.dev` 临时地址把站建起来，域名可以后补（见「共同收尾 · 绑你自己的域名」） | 在任意域名注册商处购买（国内外都行）；买完要把这个域名的 DNS 托管到 Cloudflare（在 Cloudflare 后台点「添加站点」按提示改域名的 NS 服务器，免费） | 域名本身按后缀一年几元到几十元不等；DNS 托管免费 |

### 先分清两个地方（GitHub 管代码，Cloudflare 管运行）

部署全程你只在两个网站之间来回：**GitHub 是放代码的地方，Cloudflare 是让项目跑起来的地方。** 先把这两张地图看熟，后面每一步说「去哪儿点」你就不会找错门。

**GitHub 这边（你用到的就这几样）**

| 地方 | 在哪儿 | 干什么用 |
|---|---|---|
| 仓库（Repository） | github.com 登录后，你的头像 → Your repositories | 存放本项目的全部代码文件。你 Fork 来的那份就是你的仓库 |
| Actions（工作流） | 仓库页面上方的 **Actions** 标签页 | 自动干活的机器人：部署、每周备份、每天巡检、清理、友链探活都是它按时跑的；跑完是绿勾还是红叉、日志写了什么，都在这里看 |
| Releases（发行版） | 仓库页面右侧的 Releases 一栏，或 `仓库地址/releases` | 放「发行包」给人下载的地方：手机部署包 zip 和它的校验文件在这里下 |
| Secrets（机密） | 仓库 **Settings → Secrets and variables → Actions** | 存钥匙的保险柜：部署令牌、数据库 ID、备份口令等都存在这里，填进去之后谁也看不到原文（包括你自己），部署和备份时机器人自己取用 |
| Issues（议题） | 仓库页面上方的 **Issues** 标签页 | 本项目的一个特殊用途：看门狗巡检发现站点异常时，会自动在这里开一条记录留痕；你平时不用管，收到 GitHub 通知说有新 Issue 时来这里看一眼 |

**Cloudflare 这边（只列本项目用到的）**

| 地方 | 在哪个菜单 | 管什么 |
|---|---|---|
| Pages | 左侧 **计算（Workers & Pages）** → 你的 `ym-blog` 项目 | 博客本体住在这里：访客打开的网页、后台、接口都由它跑；绑定数据库、填环境变量也都在这个项目的设置里 |
| D1 | 左侧 **存储和数据库（Storage & Databases）→ D1 SQL 数据库** | 你的文章、评论、设置存的数据库（库名 `ym-blog-db`）；建表、查数据、终极重置都在这里点 |
| R2 | 左侧 **R2 对象存储（R2 Object Storage）** | 存文件的仓库：媒体桶 `ym-blog-media` 放图片视频，备份桶 `ym-blog-backups` 放每周备份的通道一产物 |
| 域名与 DNS | 后台首页点你的域名进去 → **DNS** 页签；给博客绑域名在 Pages 项目的 **自定义域（Custom Domains）** 里 | 管「域名指向哪儿」：媒体桶绑域名、博客绑自己的域名都在这儿办 |
| API 令牌 | 右上角头像 → **我的个人资料（My Profile）→ API 令牌（API Tokens）** | 部署令牌、备份导出令牌在这里创建；创建后只显示一次，立刻存好 |

⚠️ **一个最容易找错的地方**：每周备份有两条通道——**通道一**的备份文件在 Cloudflare 的 R2 备份桶里（在博客后台「备份」页也能看到和下载）；**通道二**的加密备份文件在 **GitHub** 那边（仓库 Actions → backup 工作流的那次运行 → 页面下方的产物 Artifacts 里下载），不在 Cloudflare。找备份先想清楚要哪条通道，别跑错网站。

**两边怎么配合（一句话版）**：代码放在 GitHub → 点部署后，GitHub 的机器人把代码送到 Cloudflare 的 Pages 上跑起来 → 访客访问的是 Cloudflare 上的站 → 你写的文章存在 Cloudflare 的 D1 里、图片存在 R2 里，**都不在 GitHub**（所以 Fork 仓库带不走任何人的文章，见文末「Fork 部署与原站的区别」）。

### 术语速通（后面反复出现，先混个脸熟）

- **D1**：Cloudflare 的数据库（SQLite）。你的文章、评论、设置都存在这里。可以理解成「一张张表格组成的账本」。
- **R2**：Cloudflare 的文件仓库（对象存储）。图片、视频、备份文件都放这里，相当于一个超大网盘格子（一个格子叫一个「桶 Bucket」）。
- **Pages**：Cloudflare 托管网站的地方。把代码交给它，它给你一个能访问的网址。
- **Functions（函数）**：跟着 Pages 一起跑的一小段后端程序，负责处理登录、发文、评论这些动态请求。
- **绑定（Binding）**：在 Pages 项目设置里告诉程序「数据库用哪个、桶用哪个」的一根连线。绑定名写错或没绑，程序就找不到数据库。
- **Secret（加密变量）**：密码、密钥这类不能见光的值，在后台填的时候选「加密」，填完谁也看不到原文（包括你自己），只能重填覆盖。
- **Artifact（构建产物）**：GitHub Actions 跑完后挂在那次运行页面上的附件文件，本项目的整库加密备份就以这种形式保存。
- **Fork（复刻）**：在 GitHub 上把别人的仓库复制一份到你自己账号下，之后你改的是你那份。
- **Actions（工作流）**：GitHub 的自动干活机器。你推一次代码它自动部署，你什么都不做它也能按时自己跑备份、巡检。
- **wrangler**：Cloudflare 的命令行工具（在电脑终端里敲命令用的），方式三才需要。

## 特点：功能全清单

### ✍️ 写文章（后台 `/admin`，手机优先）

- **Markdown 编辑 + 实时预览**：预览由服务端同一个渲染器生成，和发布后的样子完全一致，不会出现「预览好好的、发出来变样」。
- **三层防丢稿**：浏览器本地自动保存 → 服务端自动保存（每人每篇一份，绝不覆盖已发布正文）→ 切后台/关页面时强制再存一次。写一半断电、误关页面，回来能接着写。
- **文章状态机**：草稿（Draft）/ 定时发布（Scheduled）/ 已发布（Published）/ 仅自己可见（Private）/ 回收站（Trash），回收站保留 30 天可还原，超时才真删。
- **定时发布不用等任务**：公开列表按「发布时间到了没有」实时判断，到点自动出现，零延迟零故障点。
- **历史版本**：发布和手动保存都会留一版，一键还原旧稿；还原前会先把当前内容再存一版，反悔也能再反悔。每篇保留最近 20 版。
- **发布面板**：自定义短链（Slug，短链接名）、标签、封面、摘要、置顶、单篇关评论、文章密码（设了密码的文章访客要输密码才能看）一处配齐。
- **模板克隆**：拿一篇旧文当模板新建，版式和写法直接复用。
- **草稿预览链接**：生成带随机口令的链接，发给朋友先看草稿；可过期、可撤销，不会被搜索引擎收录。
- **AI 写作助手（可选，自备 Key）**：接任意 OpenAI 兼容服务（OpenAI / DeepSeek / 各类中转），编辑器里一键「AI 生成摘要」「AI 生成正文」。配置在后台「站点设置 → AI 写作」（服务地址、模型、温度、两套提示词）；密钥只存服务端、页面只显示配没配，永不下发。没配置时按钮会明确提示去哪儿填，不会静默失败。（思路借鉴 EdgeBlog，见版本历史 v1.1.0）

### 🖼 发图与视频（不经过服务器中转）

- **粘贴 / 拖拽 / 多选直传**：图片和视频由浏览器拿「预签名地址（Presigned URL）」直传进 R2 存储桶，**文件字节不经过 Worker（边缘函数）**——这是铁律：免费版函数扛不了大文件流量，直传又快又不烧额度。
- **媒体库**：网格管理全部附件；可改显示名、分组（相册 Album）；删文件前会先数引用——正被文章用着的会拦下来并列出是哪几篇，防误删把文章图弄没。
- **媒体回收站**：删错了先进回收站，能还原；30 天后清理任务才真删存储对象，等不及到期也能在回收站里立即彻底删除（二次确认，还被文章引用着的会先拦下点名）。
- **视频两种来源**：本地视频直传后用站点自己的播放器播（存储桶绑了自定义域名，原生支持拖动进度）；B 站 / YouTube 只贴链接，正文单独一行就会变官方播放器。
- **组图排版约定**：一个段落里放 1 张图 = 单图大图；2 张 = 双列；3 张 = 一大多小；4 张以上 = 图集条；图片说明里加 `|长图` 后缀 = 超长截图限高展示、点开看全图。
- **大小上限（后台可调）**：图片 20MB / 视频 200MB / 文件 50MB。超大视频会提示改贴外链——外链零存储、播放更流畅，本地直传留给短视频和私密视频。
- **封面兜底**：没单独设封面时，自动取正文第一张图当封面。

### 👀 访客看的页面（服务端直出 HTML）

- **打开快**：文章正文在发布时就预渲染好存着，访客打开是直出成品页面，不等浏览器现场拼——手机弱网、微信里打开都快，分享到微信 / QQ 能带出标题和摘要。
- **阅读体验**：文章目录（TOC）可折叠、阅读进度条、代码块带复制按钮和语言标注、图片灯箱（Lightbox）点开大图可左右翻、字数与预计阅读时长、太久没更新的文章有过期提醒。
- **深色模式三段式**：跟随系统 / 固定浅色 / 固定深色，后台设置里选，默认跟随系统。
- **首页组成**：置顶 + 文章列表（卡片或紧凑列表，后台可换）、说说最新几条、那年今日（On This Day）、热门 Top 5、搜索框。
- **齐全的栏目页**：归档（按年月时间线）、标签云与标签页、说说页、友链页、关于页（就是一篇特殊文章，在后台当普通文章改）。
- **全文搜索（FTS5 + trigram）**：正文与标题建全文索引，中文按 3 字片段切分——搜任意子串都能命中并按相关度排序，不再全表扫描；两个字的短词、索引未建等情况自动退回子串匹配兜底，行为只升不降。（做法借鉴 EdgeBlog）
- **相关文章 / 上下篇**：按共同标签数自动算，不用手动维护。

### 💬 评论（自带，不挂第三方）

- **本体评论**：数据在你自己的数据库里，不依赖任何外挂评论服务（外挂哪天关停，评论不会跟着没）。
- **先审后显**：新评论默认进待审队列，后台一键通过 / 驳回 / 标垃圾 / 删除 / 回复；站长回复带身份标记。
- **老访客免审**：曾经有评论被通过过的访客，新评论可直接显示（后台可配）；含链接多的评论自动进待审。
- **防刷内置**：按 IP 频率限制（后台三档可调）、可选人机验证（Turnstile，默认关，需要时开）、评论内容一律净化转义——评论区是最常见的被黑入口，这里按最严口径处理。

### 🔐 登录与账号安全

- **账号密码登录**：单站长账号；密码只存哈希（scrypt，参数见维修手册），还加了服务端「胡椒」（Pepper，存在环境变量里、不进数据库，库被拖走也撞不开密码）。
- **登录保护**：连续失败 5 次锁定 15 分钟、再犯指数退避；错误提示恒为「账号或密码错误」，不给试探口子。
- **会话管理**：会话令牌只存哈希、有效期 7 天；每次登录都会轮换令牌并让此前的会话全部失效；能看全部登录设备、一键下线全部；改密码会自动踢掉所有设备。
- **恢复码（第一层恢复）**：后台生成 10 个一次性恢复码（只显示一次），忘密码时在登录页用任意一个码直接重置；改密后旧码全废、重新生成。
- **终极重置（第三层恢复）**：恢复码也丢了，进 Cloudflare 后台对数据库跑一句 SQL，就能回到「初始化站长」流程重设账号——完整步骤在 [MAINTENANCE.md](MAINTENANCE.md)，不依赖任何人。

### ⚙️ 站点设置（后台表单，不碰代码）

站名、介绍、头像、首页大标题与介绍文、主题色（Accent，另有 6 套配色预设一键换）、首页布局（卡片 / 列表）、卡片列数（电脑 1–4 列 / 手机 1–2 列，分开设）、文章宽度、深色策略、每页篇数、回收站天数、上传上限——全部在后台填表点选，**保存即时生效**，不用重新部署。开关组逐项都写了「关掉会怎样」：搜索、评论、评论审核、RSS（订阅源）、限流档位、人机验证、友链朋友圈抓取。AI 写作的配置也在这一页单独成卡（见「写文章」节）。

### 📊 统计与用量（心里有数）

- 浏览计数**按天聚合**：一篇文章一天只占一行数据，既不烧数据库每日额度、也不拖慢正文读写。
- 后台统计页：总阅读、近 30 天热门榜、**逐日访问量（PV）序列 + 评论趋势**、媒体用量（按图片 / 视频 / 文件分段）、内容计数、最近备份时间。

### 🧳 备份与逃生（数据永远是你的）

- **每周双通道自动备份**：通道一按表导出 JSON 存进私有备份桶（保留 12 期，带对账计数）；通道二逐表导出整库 SQL 存进 GitHub（保留 90 天），互为备份。
- **一键逃生包**：随时把全部文章导成 Markdown 文件包（带 front-matter 文件头元信息）+ 附件清单 + 评论与设置 JSON——哪天想搬去 Hugo / Astro / WordPress，原文直接能用，Cloudflare 只是托管方不是牢笼。
- **整站导入恢复**：导入前会**自动先备份当前站**，再按表导入并给出对账报告；短链冲突会自动改名并留跳转，旧链接不断。

### 🐕 全自动运维（部署完就不用管）

- **推送即部署**：代码推到 GitHub 自动上线。
- **看门狗（Watchdog）**：每天巡检首页、RSS 与健康端点，异常先复查一遍（抖动不误报），真有问题开 Issue 留痕；全好静默。
- **友链探活**：名义每 20 分钟自动查一遍友链还通不通（GitHub 官方定时常延迟数小时，另有 ym-dispatch 每 2 小时巡查、超时未跑就补发，所以真实间隔以小时计），连续失败的自动在前台置灰、后台标红。
- **每日清理**：超期回收站、过期会话、没传完的半成品记录自动清。
- **心跳保活**：超过 25 天没提交自动留一个时间戳提交，防止 GitHub 把长期不活动的定时任务停掉。

## 详情说明

**架构一句话**：访客页面和接口都由 Pages Functions（边缘函数）在请求时处理，文章存 D1（SQLite 数据库），图片视频存 R2（对象存储），一切重活（渲染、打包、统计）都挪到「发布时 / 定时任务时」做，访客读页面这条路上只做最少的事——所以快、所以省额度。

**为什么免费够用**（以官方免费额度为准，个人小站量级）：数据库每天可读 500 万行 / 写 10 万行，浏览计数按天聚合后一天一文只写一行；存储桶免费 10GB 且下载流量免费；函数每天 10 万次请求。唯一要留神的：免费额度是「超了就停到第二天早上 8 点」而不是降速，所以本站在索引、缓存、限流上都按省着用的口径设计，并留了「升到 5 美元付费版问题全消失」的预案（见维修手册）。

**数据在哪**：文章、评论、设置在你的 D1 里；图片视频在你的媒体桶里；备份在你的私有备份桶 + GitHub 里。三样都在**你自己**的账号下，不经过任何第三方。

## 部署总览

部署有三种方式。**三种方式共用的部分只做一遍**：先做「共同准备」（建数据库、建存储桶、想好几串钥匙），部署完再做「共同收尾」（初始化站长、绑域名、自查）。方式之间真正的区别，只是「把代码送上 Cloudflare」这一步怎么走。

### 部署方式对比（看完就知道选哪种）

| 对比项 | 方式一 · GitHub 连接自动部署 | 方式二 · 手机部署包 | 方式三 · wrangler 命令行 |
|---|---|---|---|
| 需要什么设备 | 手机或电脑，有浏览器就行 | 手机就行 | 必须有电脑，还要装软件 |
| 上手难度 | 中等：要配 13 个 Secret，但每项本文都给了点位 | 最低：下载、上传、点几下 | 最高：要会开终端敲命令 |
| 第一次大约耗时 | 30–45 分钟（大半花在共同准备和填 Secret 上） | 25–40 分钟（共同准备照做，省了配 GitHub 的时间） | 30–60 分钟（看电脑熟练度） |
| 日常更新方不方便 | 最方便：改完代码推一下，自动上线 | 最不方便：每次更新都要下新包、重新上传一遍 | 一般：改完敲一条命令部署 |
| 出错了好不好排查 | 好：Actions 页面有完整运行日志，哪一步红了一眼看到 | 一般：控制台只有部署记录，细节少 | 好：报错直接打在终端里，信息最全 |
| 自动任务（备份/巡检） | 全套现成：工作流就在仓库里，配好 Secret 自己跑 | **没有**：备份、巡检这些 GitHub 工作流不在部署包里，要全套自动运维就得回头配方式一的仓库和 Secret | 可以有：代码在本地仓库里的话，把 Secret 配进 GitHub 后同样能跑 |
| 适合谁 | 大多数人，尤其打算长期用、想要自动备份的人 | 临时救急、迁移到另一个账号、或先把站立起来再说的人 | 本来就会用终端、或要在电脑上改代码调试的人 |

一句话建议：**长期用就选方式一**；只想先把站跑起来、或在救急，就用方式二把站立住，之后随时能补上方式一（数据都在数据库和桶里，换部署方式不丢数据）。

## 共同准备：先建好数据库和存储桶

下面四步，三种方式都要做（方式二、三同样需要）。示例里 `blog.example.com` 是你的博客域名、`media.example.com` 是媒体域名（一般用博客域名的子域名，如 `media.blog.example.com`），照着换成你自己的即可。

### 第 1 步：把仓库复制到自己名下（Fork）

> 方式二可以跳过本步（你直接下部署包）。方式一必做；方式三也可以不 Fork、直接下源码，但 Fork 一份更方便日后同步与开自动任务。

1. 打开本仓库的 GitHub 页面，点右上角的 **Fork**（复刻）按钮。
2. 在打开的页面里，仓库所有者（Owner）选你自己的账号，仓库名保持 `ym-blog`，点 **Create fork**。
3. 等页面跳到你自己账号下的 `ym-blog` 仓库。
   做到这里你应该看到：仓库地址变成了 `github.com/你的用户名/ym-blog`，页面顶部有一行小字写着 forked from（源自）原仓库。

### 第 2 步：建数据库 D1，并把表建好（跑 schema）

「跑 schema」就是把仓库 `schema/` 文件夹里的几个 `.sql` 文件依次在数据库里执行一遍，把文章、评论这些表建出来。一步都不能少、顺序不能反。

![D1 数据库后台](https://gcore.jsdelivr.net/gh/YiMing918/ym-blog@main/docs/cf-d1.png)
*建好后的 D1 数据库页（真实后台截图，演示数据）：表建好后能在这里逐张核对，执行初始化脚本也在这个控制台里粘贴运行。*

1. 打开 [dash.cloudflare.com](https://dash.cloudflare.com) 登录 → 左侧菜单点 **存储和数据库（Storage & Databases）→ D1 SQL 数据库（D1 SQL Database）**。
2. 点右上角 **创建（Create）** → 名称输入框填 `ym-blog-db` → 点创建。
3. 在数据库列表里点进刚建好的 `ym-blog-db` → 点上方的 **控制台（Console）** 标签页。你会看到一个大的文本输入框，这就是粘贴 SQL 执行的地方。
4. 打开仓库里的 `schema/0001_init.sql`：在 GitHub 仓库页面点 `schema` 文件夹 → 点 `0001_init.sql` → 点右上角的复制按钮（或打开 Raw 原始文件全选复制），把**全部内容**复制下来。
5. 回到 D1 控制台，把内容粘贴进输入框 → 点 **执行（Execute）**。
   做到这里你应该看到：页面提示执行成功，回到数据库的「表」列表能看到共 **21 张表**。
6. 用同样的方法，依次把 `0002_seed.sql`（初始设置和示例文章）、`0003_fts.sql`（全文搜索索引）粘贴执行一遍。每执行完一个，都会提示成功。
7. 再依次执行 `0004_media_trash.sql` 和 `0005_comment_trash.sql`（给回收站功能补的字段）。**注意：这两个文件是「加一列」的语句，同一份只能执行一次**；万一你重复粘贴执行，会报错说列已存在——报错就说明已经加过了，跳过即可，不会损坏数据。（第 4、5 号是给老版本升级留的，新部署照样一次跑齐最省事。）
8. 回到这个数据库的详情（概述）页，找到 **Database ID（数据库 ID）**——一串类似 `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` 的字符，先记在记事本里，后面配 Secret 和 wrangler 时要用。查它的方法和性质见下面「钥匙和编号」第 9 条。

### 第 3 步：建两个存储桶 R2，并配好媒体桶

![R2 存储桶后台](https://gcore.jsdelivr.net/gh/YiMing918/ym-blog@main/docs/cf-r2.png)
*R2 桶列表（真实后台截图）：媒体桶与备份桶两个分开建；媒体桶还要绑一个自定义域名，图片视频才能公开访问。*

1. 左侧菜单点 **R2 对象存储（R2 Object Storage）**。如果你从没用过 R2，页面会先让你绑一张银行卡开通（免费额度内不扣费）——按页面提示走完这一步，才能建桶。
2. 点 **创建存储桶（Create bucket）** → 名称填 `ym-blog-media` → 点创建。这是**媒体桶**，存你上传的图片和视频。
3. 再点一次创建，名称填 `ym-blog-backups` → 创建。这是**备份桶**，存自动备份。**备份桶不要绑任何公开域名**，保持私有。
4. 给媒体桶绑一个能公开访问的域名：点进 `ym-blog-media` → 点 **设置（Settings）** 标签 → 找到 **自定义域名（Custom Domains）** 一栏 → 点 **连接域名（Connect Domain）** → 输入框填 `media.example.com`（换成你的媒体域名）→ 按提示确认。
   做到这里你应该看到：这条域名的状态从「初始化」变成 **活动（Active）**（可能要等几分钟）。生效后，你的图片视频就会从这个域名公开访问。
   ⚠️ 不要用桶自带的 `r2.dev` 域名凑合：官方对它限流，会随机报 429 错误，图片时好时坏。
5. 给媒体桶配 CORS（跨域许可，不配的话浏览器直传图片会被拦）：还在媒体桶的 **设置（Settings）** 页 → 找到 **CORS 政策（CORS Policy）** → 点添加/编辑 → 填一条规则：允许的来源（Allowed Origins）填你的博客域名 `https://blog.example.com`，允许的方法（Allowed Methods）勾上 `PUT` 和 `GET` → 保存。
6. 创建直传用的 S3 凭据（是什么、丢了怎么办见「钥匙和编号」第 6 条）：回到 R2 总览页 → 点右上角 **管理 R2 API 令牌（Manage R2 API Tokens）** → 点 **创建 API 令牌（Create API Token）** → 权限选 **对象读写（Object Read & Write）**，指定存储桶只选 `ym-blog-media` → 点创建。
   做到这里你应该看到：页面显示出一对 **Access Key ID** 和 **Secret Access Key**，并且明确提示只显示这一次。**立刻**把这两串都抄进你的记事本/密码管理器再关页面。
7. 顺带记下 **Account ID（账号 ID）**：R2 总览页或 Cloudflare 后台首页右侧能看到，一串 32 位字符。你的 S3 端点就是把账号 ID 拼进去：`https://<账号ID>.r2.cloudflarestorage.com`，后面配变量要用。

### 第 4 步：先想好三串随机字符

有三个值需要你**自己编**一串随机字符（建议每串至少 32 位，字母+数字混合，可以用密码管理器生成）：**密码胡椒**、**任务密钥**、**备份加密口令**。现在先编好、存进密码管理器，后面配 Secret 时直接取用。它们分别是什么、丢了会怎样，下面「钥匙和编号」第 3、4、5 条写得很细，**配之前务必看完**。

## 全程要碰到的钥匙和编号（逐样说清）

部署和使用全程会遇到下面这些密码、令牌和 ID。每一样都按五点讲：**是什么 / 去哪拿 / 填到哪 / 干什么用 / 怎么保存、丢了怎么办**。先认全了再动手配，能少踩很多坑。

### 1. 管理员（站长）账号密码

- **是什么**：你登录博客后台 `/admin` 用的账号密码，只有你一个人有。
- **去哪拿**：没有人发给你——部署完成后第一次打开后台时，你在初始化页面上**自己设定**（见「共同收尾」）。
- **填到哪**：只在初始化那一刻填进网页表单；系统只保存它的哈希（打乱后的指纹），任何地方都查不到原文。
- **干什么用**：登录后台写文章、审评论、改设置。
- **保存与丢失**：存进密码管理器。忘了也别慌，有三层自救：① 登录页用**恢复码**重置（见第 2 条）；② 恢复码也丢了，按 [MAINTENANCE.md](MAINTENANCE.md) 的「终极重置」进 Cloudflare 后台对数据库跑一句 SQL，重新走初始化。都不需要求任何人。

### 2. 恢复码（10 个一次性码）

- **是什么**：初始化站长时页面给出的一组备用钥匙，每个码只能用一次。
- **去哪拿**：初始化成功的页面上，**只显示这一次**，页面关掉就再也看不到（库里只存哈希）。
- **填到哪**：忘密码时，在登录页点「忘记密码？用恢复码重置」，填用户名 + 任意一个没用过的码 + 新密码。
- **干什么用**：忘密码时的第一层自救，1 分钟重置完。
- **保存与丢失**：出现的那一刻立刻截图 + 存进密码管理器，最好再抄一份在纸上分开存。改过密码后旧码全部作废，要在后台「账号安全」里**重新生成一组**并重新保存。10 个全丢了也不怕，走第 1 条说的终极重置。

### 3. ★ 备份加密口令（最重要，务必看完）

- **是什么**：一串由你自己编的字符（在 GitHub 里它的名字叫 `BACKUP_PASSPHRASE`）。每周自动备份的「通道二」会把整个数据库导出成一个 SQL 文件，**上传到 GitHub 之前先用这串口令加密**（公开仓库的产物任何人都能下载，不加密等于把数据库公开）。
- **去哪拿**：没有任何地方生成它——你自己编一串足够长的随机字符（建议 20 位以上，用密码管理器生成）。
- **填到哪**：只填一个地方：你的 GitHub 仓库 → **Settings → Secrets and variables → Actions** → 新建名为 `BACKUP_PASSPHRASE` 的 Secret。**没配它时，通道二只做导出校验、不上传产物**（这是故意的安全设计，不是故障）。
- **干什么用**：给每周整库备份上锁。将来真要恢复时，用同一串口令把备份文件解开（步骤见「备份与恢复」一节）。
- **保存与丢失**：⚠️ **它是唯一钥匙，丢了就永远解不开已有的加密备份，任何人——包括 Cloudflare、GitHub 和本项目作者——都没办法帮你恢复，没有例外。** 保存办法：① 存进密码管理器（和博客恢复码分开两条存）；② 再抄一份在纸上，放在家里安全的地方；③ 不要只存在某一台手机或某一个聊天记录里。以后还会用到它的场合：每次恢复整库备份时解密，以及你想换口令时（换口令只影响之后的新备份，老备份仍用老口令解，所以老口令也要一直留着）。

### 4. 密码胡椒（PASSWORD_PEPPER）

- **是什么**：一串你自己编的随机字符，给站长密码的哈希再加一层「料」。
- **去哪拿**：自己编（至少 32 位随机字符，用密码管理器生成）。
- **填到哪**：Pages 的加密变量里。方式一的人填进 GitHub Secret 同名项，部署流水线会自动灌进 Pages；方式二、三的人在 Pages 后台/命令行手动加。
- **干什么用**：就算数据库文件被人拿走，没有这串胡椒也撞不开站长密码。
- **保存与丢失**：存进密码管理器。**上线后永远不要改它**——改了之后，所有旧密码（站长密码、文章密码）都会验证不过，等于全站密码作废。它丢了怎么办：站长还能用恢复码/终极重置重设密码，但文章密码会失效；所以别丢。

### 5. 任务密钥（TASK_SECRET）

- **是什么**：一串你自己编的随机字符，是自动任务敲你站点接口时的通行证。
- **去哪拿**：自己编（至少 32 位随机字符）。
- **填到哪**：两个地方填**同一个值**：GitHub Secret 里一份、Pages 加密变量里一份。方式一的人只填 GitHub 那份，流水线自动灌进 Pages，两边天然同值；方式二、三的人要手动在 Pages 里加同值的一份。
- **干什么用**：看门狗巡检、友链探活、每日清理、每周备份这些自动任务，每次调用站内 `/api/tasks/*` 接口都要出示它，对不上就拒绝——防止陌生人乱调你的任务接口。
- **保存与丢失**：存进密码管理器。丢了不致命：自己编一串新的，两边（GitHub Secret 和 Pages 变量）一起换成新值、重新部署一次即可，没有数据损失。

### 6. R2 S3 凭据（Access Key ID + Secret Access Key）

- **是什么**：一对钥匙（一个 ID + 一个密钥），是你媒体桶的专用门卡。
- **去哪拿**：Cloudflare 后台 → R2 总览页 → 管理 R2 API 令牌 → 创建时生成（共同准备第 3 步第 6 小步）。**Secret Access Key 只在创建那一刻显示一次。**
- **填到哪**：Pages 的加密变量 `R2_ACCESS_KEY_ID` 和 `R2_SECRET_ACCESS_KEY`（方式一经 GitHub Secret 灌入）。
- **干什么用**：你在后台传图片时，程序用这对钥匙签发一张「临时直传地址」，浏览器拿着它把图片直接传进媒体桶（文件不经过服务器，靠的就是这一步）。
- **保存与丢失**：创建时立刻存进密码管理器。忘了或丢了：回 R2 令牌页把旧令牌删掉、重新建一枚新的，把新的一对更新进 Secret 并重新部署即可，不影响桶里已有的图片。

### 7. 部署令牌（CLOUDFLARE_API_TOKEN）

- **是什么**：一把让 GitHub Actions 有权替你部署的 Cloudflare 令牌。只有方式一需要。
- **去哪拿**：打开 Cloudflare 后台 → 点右上角头像 → **我的个人资料（My Profile）→ API 令牌（API Tokens）** → 点创建 → 选「编辑 Cloudflare Workers（Edit Cloudflare Workers）」模板，再按提示补上 D1、R2、Pages 的编辑权限 → 创建后复制令牌（只显示一次）。
- **填到哪**：GitHub 仓库的 Secret `CLOUDFLARE_API_TOKEN`；和它搭档的 `CLOUDFLARE_ACCOUNT_ID` 填你的账号 ID（第 3 条钥匙里说的那串，在后台首页右侧能看到）。
- **干什么用**：部署流水线拿它登录你的 Cloudflare 账号，把代码部署到 Pages、把 Secret 灌进 Pages。
- **保存与丢失**：存进密码管理器。怀疑泄漏时：回 API 令牌页把旧令牌撤销（删除），建一枚新的换进 GitHub Secret 即可，站点本身不受影响。

### 8. 备份导出令牌（D1_EXPORT_TOKEN）

- **是什么**：一枚**只给读权限**的专用令牌，和部署令牌分开，不混用。只有方式一（自动备份通道二）需要。
- **去哪拿**：同第 7 条的 API 令牌页 → 创建自定义令牌 → 权限只加一条 **账号（Account）· D1 · 读取（Read）** → 创建后复制。
- **填到哪**：GitHub 仓库的 Secret `D1_EXPORT_TOKEN`。
- **干什么用**：每周备份通道二导出整库数据时用它读数据库。它只有读权限，就算泄漏也改不了你的数据。
- **保存与丢失**：存进密码管理器。丢了就删旧建新、换进 Secret；没配它时通道二自动跳过，通道一（存备份桶的备份）不受影响。

### 9. 两个 ID：Database ID 和 Account ID（不是秘密）

- **是什么**：数据库和账号的门牌编号，**不是密码、不算秘密**，写在文档和配置里都没关系。
- **去哪拿**：随时能查——Database ID 在 D1 数据库的详情（概述）页；Account ID 在 Cloudflare 后台首页右侧、或 R2 总览页。
- **填到哪**：Database ID 填 GitHub Secret `D1_DATABASE_ID`（方式一）或 wrangler.toml 的 `database_id`（方式三）；Account ID 填 GitHub Secret `CLOUDFLARE_ACCOUNT_ID`，并用来拼 S3 端点地址。
- **干什么用**：让部署工具知道「把代码部署到哪个账号、绑哪个数据库」。
- **保存与丢失**：不用刻意保存，忘了就回控制台查。填错的后果通常是部署时报错说库不存在，按报错回来核对即可。

### 10. 人机验证密钥（TURNSTILE_SECRET，可选）

- **是什么**：Cloudflare 人机验证（Turnstile，就是「证明你不是机器人」那个小方框）的服务端密钥。
- **去哪拿**：只有当你想开评论区人机验证时才需要：Cloudflare 后台 → Turnstile 页 → 添加小部件时生成，站点密钥（Site Key）填进后台设置、密钥（Secret Key）填这里。
- **填到哪**：Pages 加密变量 `TURNSTILE_SECRET`。
- **干什么用**：评论提交时在服务端核对访客是不是机器人。
- **保存与丢失**：不开这个功能就完全不用管它；开了又丢了，回 Turnstile 页重新生成一枚换上即可。

## 方式二：手机部署包（控制台上传）

**它的优势**

- 不碰 GitHub 配置：不用 Fork、不用填 13 个 Secret，下载、上传、点几下就上线。

- **Q：首页是 404、或页面没样式、后台 `/admin` 打不开？**
A：几乎可以肯定是**下错了包**——把普通部署包或 Source code 拿来直传了。CF 控制台拖拽上传不会编译 `functions/` 文件夹：本站全部页面都靠后端出，下错包时连首页都是 404；样式和后台能打开一半的情况，多半是包不完整或传漏了文件。直传只认带 `-worker-` 的直传专用包（根目录直接躺着 `_worker.js`、`_routes.json`、`admin/`、`assets/`），重新下对再传。（用 Git / wrangler 路线的人另查：`_routes.json` 是那条路的路由命脉，少了它样式、脚本和后台页面会全部 404，详见「已知边界」最后一条。）
- **Q：绑定和变量都配了，站点还是报找不到数据库？**
A：两个高频原因：① 绑定变量名写错，必须正好是 `DB`、`MEDIA`、`BACKUPS`，全大写；② 配完没重新部署——绑定和变量只对**新部署**生效，回部署页重试一次。
- **Q：图片传不上去？**
A：按顺序查：Pages 变量里 `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` 填了没、填错没；媒体桶的 CORS 配了没（共同准备第 3 步第 5 小步）；文件是不是超过后台设的上限（图 20MB / 视频 200MB）。

## 方式三：wrangler 命令行部署

**它的优势**

- 过程最透明：每条命令的输出直接打在终端上，出错信息最完整，排查最快。
- 适合顺手改代码的人：代码就在本地，改完一条命令就部署，不用先推 GitHub。
- 数据库操作最顺手：远程执行 schema、导入备份 SQL 都是一条命令的事（恢复整库备份时尤其方便）。

**它的劣势**

- 门槛最高：要装 Node.js、会开终端敲命令，纯新手容易卡在环境上。
- 真值要写进本地的 wrangler.toml 文件：文件管不好（比如误传公开仓库）会把数据库 ID、端点带出去（ID 不是密钥，但习惯要养成）。
- 自动运维不会自己长出来：备份、巡检仍要回 GitHub 仓库配 Secret 并启用 Actions 才跑（等于还要做方式一的 GitHub 那半套）。

###

- 一台电脑（Windows / Mac / Linux 都行）和终端；
- Node.js 18 以上（去 [nodejs.org](https://nodejs.org) 下 LTS 版安装包一路下一步即可）；
- 本仓库源码：GitHub 仓库页点 **Code → Download ZIP** 解压，或用 git 克隆你 Fork 的仓库；
- 共同准备建好的 D1/R2，以及你的 Database ID、Account ID、S3 端点和四个必填 Secret 的值（见「钥匙和编号」）。

## 共同收尾：初始化站长、绑域名、自查

三种方式部署完都要做这三件事，做完才算真正交付。

### 第 1 件：初始化站长，并收好恢复码（最重要，别跳）

1. 打开 `https://你的站点地址/admin`（先用 pages.dev 地址就行）。第一次打开会进入「初始化站长」页。
2. 在用户名框填你想用的站长用户名，密码框填一个**至少 8 位**的密码 → 点创建。
3. 页面会显示 **10 个恢复码，只显示这一次**。
做到这里你应该看到：恢复码明明白白列在页面上、还没进后台首页。**先别点走**——立刻截图并存进密码管理器（为什么重要、丢了怎么办，见「钥匙和编号」第 1、2 条）。
4. 存好后进后台首页，顺手到「站点设置」把站名、介绍改成你自己的。
⚠️ **v1.2.5 起初始化必须先配 `SETUP_TOKEN`**：在 Pages 后台 → 设置 → 环境变量里先加一个加密变量 `SETUP_TOKEN`（自己编一串至少 32 位的随机字符，存进密码管理器），初始化页面上要填对这串口令才给建站长号；**没配 `SETUP_TOKEN` 时初始化会被直接拒绝**（这是故意的安全门，防的是部署完成到你初始化之间被人抢注）。环境变量预置的 `INITIAL_ADMIN_*` 建号路径同样受这道门约束。部署完仍请尽快初始化，不要把未初始化的站点长时间挂在公网上。本方案只走这条页面初始化路，**不要用环境变量预置站长密码**（不要配 `INITIAL_ADMIN_PASSWORD`，原因见配置表）。

### 第 2 件：绑你自己的域名（没有域名可跳过，之后再补）

1. 前提：你的域名 DNS 已托管在 Cloudflare（域名出现在你 CF 后台的站点列表里）。
2. 打开 Cloudflare 后台 → **计算（Workers & Pages）→ ym-blog → 自定义域（Custom Domains）→ 设置自定义域（Set up a custom domain）** → 输入框填 `blog.example.com`（换成你的博客域名）→ 按提示确认。
做到这里你应该看到：这条域名状态变成活动（Active），证书由 Cloudflare 自动签发（可能等几分钟）。之后用你的域名就能打开博客。
3. 域名生效后，回 GitHub 仓库 → Settings → Secrets → 点 `SITE_URL` → 把值改成 `https://blog.example.com`（你的正式域名）→ 保存。看门狗、探活、清理、备份四个任务工作流都按这个地址找你的站，填错了它们会去敲旧地址。
4. （可选）想让 RSS 和站点地图固定用正式域名拼链接：去 Pages 后台手动加一个普通变量 `SITE_BASE_URL`、填同一个地址即可。不加也行，站点会按访客实际用的域名推导。媒体域名在共同准备第 3 步已经绑好，这里不用再动。

### 第 3 件：上线后自查清单

逐项做完，六项全过才算部署成功：

- [] 首页能打开、示例文章在；把站名/介绍在后台「站点设置」改成自己的。
- [] 后台发一篇测试文章，插一张图、传一个小视频，发布后前台能看、图能点大、视频能播。
- [] 用没登录的浏览器给文章留一条评论，确认它先进了后台待审队列，你通过后才出现。
- [] 后台「备份」页点一次「立即备份」，确认备份列表里多了一条、能下载。
- [] 「备份与数据」里点一次「导出 Markdown 逃生包」，确认能下载 zip。
- [] 删掉示例文章和示例说说（会先进回收站，30 天内可还原，属正常流程）。

这是本方案实际在用的全清单。`deploy` 流水线每次运行时，会用其中的真值替换 `wrangler.toml` 占位、并把运行时密钥灌进 Pages 加密变量——所以这 13 项是唯一的「真值存放处」，除 GitHub 加密库与 Pages 生产环境外，真值不要出现在任何其他地方（包括仓库文件与聊天记录）。

| Secret | 用途 |

## 探活：怎么知道站点还活着

「探活」就是每隔一段时间自动去敲一下你的站点，看它还应不应答。本站有两层探活，分工不同：

**第一层 · 站长总览探活（本站作者在用 ym-dash）**

- **需要什么**：一个会定时发请求的探活工具。本站作者用的是自建的测活总览 **ym-dash**（一个单独的小项目，里面有个探活 Worker，每 30 分钟自动把登记的站点挨个请求一遍）。你没有 ym-dash 也没关系：任何「网站可用性监控」类服务（如 UptimeRobot 一类）填上你的博客地址，效果一样；或者干脆靠下面第二层看门狗，它本身就带巡检。
- **怎么加（以 ym-dash 为例）**：打开 ym-dash → 登录后台 → 站点管理 → 添加站点 → 名称填「博客」，URL 填 `https://blog.example.com`（换成你自己的博客地址）→ 保存 → 点一次「立即检测」，看到返回 200、耗时几百毫秒就是通的。之后每 30 分钟自动探，结果在 ym-dash 总览页看：每站一行，正常/异常和响应毫秒数一目了然。
- **探什么才算真活**：只探到「返回 200」还不够稳——要探**首页地址**且返回的是博客首页内容（标题、示例文章都在），才说明访客侧真的能用。更深一层再验 `/admin` 能出登录/初始化页，说明函数和数据库也通。本站的看门狗就是按「首页 + RSS + 健康端点」三处一起探的，比只探首页可靠。

**第二层 · 看门狗自检（仓库自带，方式一配好就自动有）**

- 每天北京时间 08:23 自动巡检首页、RSS 和健康端点，异常会**先复查一遍**（防止网络抖动误报），确认真有问题才在你的 GitHub 仓库开一条 Issue 留痕；全好就静默，什么都不发。
- 在哪看：仓库 **Issues** 页有新条目 = 它报警了；仓库 **Actions → watchdog** 能看每天的巡检日志。
- 注意：看门狗只在「方式一」下工作（它跑在 GitHub Actions 里）；只用部署包上线的人没有这一层，建议至少配一个第三方探活盯首页。

## 保活：平时要盯什么

**结论先行：站点本身不需要保活。** Pages 没有休眠机制，不用定期去点它、刷它防关停。真正需要「保」的是 GitHub 那边的定时任务和几样身外之物：

| 要盯的事 | 为什么 | 怎么做 |
|---|---|---|

## 自动更新与自动任务

代码更新（方式一）：你往 GitHub 仓库 `main` 分支推一次代码，部署工作流就自动把新版上线，不需要任何额外操作。其余自动任务都在 GitHub Actions 里，全表如下（只用方式二上线的人没有这一套，见方式二的劣势说明）：

| 什么在自动跑 | 谁触发 | 频率 | 在哪看 | 怎么手动触发 | 失败了怎么办 |
|---|---|---|---|---|---|
| 部署 deploy | 你推送代码到 main（或手动点） | 每次推送 | 仓库 Actions → deploy | Actions 页选 deploy → Run workflow | 看运行日志红在哪一步（多半是 Secret 缺项或填错），补齐后重跑；修不好时上一个版本还在线上跑着，不影响访问 |
| 看门狗 watchdog | GitHub 定时（带心跳保活） | 每天 08:23（北京时间） | Actions → watchdog；异常看 Issues | Actions 页选 watchdog → Run workflow | 巡检失败会开 Issue 说明查到什么；若工作流本身报错，先看日志里是站点真挂了还是 `SITE_URL`/`TASK_SECRET` 配错了 |
| 友链探活 friend-check | GitHub 定时 + 外部调度器（ym-dispatch）巡查补发 | 名义每 20 分钟；GitHub 定时常延迟数小时，外部调度器约每 100 分钟查一次、发现超时未跑就补发，所以真实间隔以小时计 | Actions → friend-check；结果回写到站点：连续失败的友链前台置灰、后台标红 | Actions 页选 friend-check → Run workflow | 个别友链失败是对方的事，站点会自动标红不用你管；整批失败先查 `TASK_SECRET` 与站点任务接口是否正常 |
| 每日清理 purge | GitHub 定时 | 每天凌晨 03:17（北京时间） | Actions → purge | Actions 页选 purge → Run workflow | 清理的是超期回收站、过期会话、半成品记录，漏跑一两天无大碍；连续失败看日志，多半是任务密钥对不上 |
| 每周备份 backup | GitHub 定时 | 每周一凌晨 04:41（北京时间） | Actions → backup；产物去向见下一节 | Actions 页选 backup → Run workflow（建议配完 Secret 后先手动跑一次验通） | 任一通道失败工作流会变红示警、绝不装睡；按日志查：通道一多半是 `TASK_SECRET`/`SITE_URL`，通道二是三个导出相关 Secret 或备份口令没配 |

本地冒烟测试：仓库带了零依赖的自检脚本（需要 Node ≥ 22.5），改代码后先跑一遍再推：`npm run smoke` —— 用真迁移 SQL + 内存替身把登录、发文、评论、直传登记、导出、任务整条链走一遍，全绿才算没改坏。

## 安全提醒：这些东西不能发给任何人

下面这些东西，任何一个泄露出去，别人就能动你的站，所以**不能发给任何人、不能出现在截图里、不能写进公开仓库**：

- **管理员密码、恢复码**：等于后台大门的钥匙和备用钥匙。
- **备份加密口令**：能解开你的整库备份（见「钥匙和编号」第 3 条）。
- **各种 Secret 和令牌**：密码胡椒、任务密钥、R2 的 S3 密钥、Cloudflare API 令牌、D1 导出令牌、人机验证密钥——每一把都是「钥匙和编号」那一节里逐样讲过的。

日常习惯，照着做就行：

1. **截图前先打码**：发教程、找人求助、贴报错图之前，把上面这些值全部涂掉再发。报错信息本身可以发，值不行。
2. **两个总闸账号都开两步验证（2FA）**：GitHub 账号管着代码和备份产物，Cloudflare 账号管着站点和全部数据——这两个账号的密码 + 两步验证守住了，站基本就稳了。开法都在各自网站的「账号设置 → 安全」里，跟着提示绑手机验证器即可。
3. **钥匙只存两个地方**：密码管理器 + 一份离线纸质备份（恢复码和备份口令尤其要），不要只存一张手机截图——手机丢了你就跟着丢了。
4. **千万别把密钥提交进 GitHub 仓库**：仓库是公开的，一旦提交，哪怕随后删掉文件，历史记录里还留着，等于已经泄露。万一真误提交了，正确做法是**立刻把那把钥匙作废、重建一把新的**（删文件不算处理完）。

## 手机能干哪些、哪些事建议用电脑

**日常的事，手机全能办**（这也是本站后台按手机优先设计的原因）：

- 部署方式二的全程（下载部署包、控制台上传、绑域名）；
- 写文章、发图片视频、审核评论、改站点设置、看统计；
- 通道一备份的下载与整站导入恢复；
- 在 GitHub 手机网页/App 上改仓库 Secrets、手动触发工作流、看运行日志。

**只有两类事建议用电脑**，不是手机办不了，是手机办起来太受罪：

- **通道二整库恢复**：要开终端跑 OpenSSL 解密 `.enc` 文件，再用 wrangler 把几 MB 的 SQL 整文件导入 D1。手机上没有顺手的终端工具，硬要用 D1 控制台分段粘贴 SQL 也行，但解密那一步绕不过去。
- **方式三 wrangler 部署、大批量改代码**：wrangler 本来就是电脑上的命令行工具。

一句话：**平时维护全靠手机没问题；真到了「整库恢复」这种大抢修，借台电脑一次办完。**

## 备份与恢复（手把手）

### 先分清：你的备份有两条通道

| 通道 | 备份的是什么 | 存在哪 | 保留多久 | 恢复方式 |
|---|---|---|---|---|
| 通道一 | 按表导出的整站 JSON（文章、评论、设置等） | Cloudflare 的 R2 备份桶（私有） | 最近 12 期 | 后台「备份」页下载后，在后台导入恢复（最常用、最简单） |
| 通道二 | 整库 SQL 文件（经备份口令加密） | GitHub 仓库 Actions 的运行产物（Artifact），名字叫 `d1-export` | 90 天 | 先下载、用备份口令解密，再把 SQL 导入 D1（整库级恢复，最后手段） |

另外还有随用随取的**逃生包**：后台「备份与数据」→「导出 Markdown 逃生包」，把全部文章导成 Markdown 文件打包下载——那是给你搬家到别的博客系统用的，不是恢复本站用的，别搞混。

### 日常恢复（优先用这条）：通道一整站导入

1. 打开你的博客后台 → 进 **「备份」** 页 → 在备份列表里找到要恢复的那一期 → 点下载，得到一个 JSON 文件。
   做到这里你应该看到：文件下到本地了，名字里带着备份日期。
2. 还在后台 → 进 **「备份与数据」** → 找到整站导入入口 → 选刚下载的 JSON 文件 → 确认导入。
   做到这里你应该看到：导入前系统会**自动先把当前站备份一份**（防导错了没退路），然后按表导入，最后给出对账报告。
3. 逐项对一眼对账报告（导入了几篇、几个附件、短链冲突自动改了哪些名），再打开首页和几篇文章抽查。
   做到这里你应该看到：内容回到备份那一刻的样子，旧链接因为有跳转也不会断。

### 整库恢复（通道二，站坏得比较彻底时才用）

> 前置条件：你得有**备份加密口令**（见「钥匙和编号」第 3 条）。没有口令，这条通道的备份解不开，只能走通道一。

1. **下加密包**：打开你的 GitHub 仓库 → 点上方 **Actions** → 左侧选 **backup** 工作流 → 点最近一次成功的那行运行记录 → 拉到页面下方 **Artifacts（产物）** 一栏 → 点 `d1-export` 下载，解压后得到 `backup-d1.sql.enc`（这就是加密的整库 SQL）。
   做到这里你应该看到：本地有了那个 `.enc` 文件。注意产物只保留 90 天，要长期留档就把 `.enc` 文件自己再存一份（它是加密的，存哪都安全）。
2. **解密**：在电脑上装好 OpenSSL（Mac/Linux 一般自带；Windows 可用 Git Bash 自带的），在 `.enc` 文件所在目录打开终端，执行：
   ```bash
   openssl enc -d -aes-256-cbc -pbkdf2 -in backup-d1.sql.enc -out backup-d1.sql -pass pass:<你的备份加密口令>
   ```
   把 `<你的备份加密口令>` 换成你存的那串（连同前面的 `pass:` 一起，口令本身别带尖括号）。
   做到这里你应该看到：同目录多出一个 `backup-d1.sql`，用文本编辑器打开开头能看到正常的建表语句。**如果口令错了，解出来的会是乱码或命令直接报错**——先核对口令再往下走，别拿乱码文件去导入。
3. **导入回 D1**：推荐用 wrangler 一条命令整文件导入（文件通常有几 MB，控制台网页粘贴容易截断）：
   ```bash
   npx wrangler d1 execute ym-blog-db --remote --file backup-d1.sql
   ```
   没有 wrangler 的话，也可以去 Cloudflare 后台 → D1 → `ym-blog-db` → 控制台（Console），把 SQL 分段粘贴执行，但务必从头到尾按顺序贴完、别漏段。
   做到这里你应该看到：命令输出执行成功。SQL 文件**末尾自带一条全文索引重建语句**，跑完搜索就恢复正常，不用你另做处理。
4. **重新初始化站长**：通道二的产物出于安全，**凭据类表只导出结构、不导出数据**（站长账号、会话、恢复码都不在备份里）。所以恢复完打开 `/admin`，你会回到「初始化站长」页——重新设一次用户名密码、收好新给的恢复码即可（见「共同收尾」第 1 件）。
5. **抽查**：打开首页、随机点开 3 篇文章、搜一个旧文章里的词、看一张老图片显示正常。
   做到这里你应该看到：内容和备份时刻一致，搜索能搜到，图片能显示。媒体文件本体一直在 R2 媒体桶里，不受这次恢复影响，不用动。

### 演练（每季度做一次，别等真出事才第一次恢复）

1. 先在后台「备份」页点一次「立即备份」，确认通道一新出一期、能下载。
2. 再去 Actions → backup 手动 Run 一次，确认运行变绿、产物 `d1-export` 出现，下载下来用你的口令在本地解一次——**能解开、解出来是正常 SQL**，就证明口令和备份都是好的。
3. 有空余设备/测试站时，把通道一 JSON 真导入一次验成色；没条件时至少做到第 2 步。整个演练 10 分钟，比真出事时现学便宜得多。
## 常见问题 FAQ

**Q：真的完全免费吗？**
A：个人小站量级在免费额度内是真免费。唯一的开通动作：用 R2 前 Cloudflare 要你绑一张卡（免费额度内不扣费）。将来量真的大到顶了，升 Workers Paid（付费版，5 美元/月）后额度问题基本全消失，本站设计时已把这条路留好。

**Q：手机上能完成全部操作吗？**
A：能。后台就是按手机优先做的：写文章、传图传视频、审评论、改设置、看统计、跑备份，都在手机浏览器里点完。电脑上只是屏幕更宽，没有「电脑专属功能」。

**Q：忘了后台密码怎么办？**
A：三层自救，都不用求人：①登录页用恢复码重置（初始化站长时让你存的那 10 个码）；②恢复码也丢了——第二层（任务密钥开窗口）本版未实现，跳到③；③进 Cloudflare 后台按 [MAINTENANCE.md](MAINTENANCE.md) 的「终极重置」对数据库跑一句 SQL，重新初始化站长。详见维修手册。

**Q：图片视频传不上去？**
A：先看报错：提示超上限就是文件太大（视频可改贴外链）；提示类型不支持是格式不在白名单；一直转圈多半是媒体桶的 CORS 没配或配错（照部署第 3 步重配）。还不行看维修手册故障对照表。

**Q：评论提交了却不显示？**
A：默认先审后显——去后台「评论管理」的待审队列里通过它。若你不想审，在设置里关掉「评论审核」。

**Q：我的文章和数据到底存在哪、安不安全？**
A：全在**你自己**的 Cloudflare 账号里（D1 数据库 + R2 桶），代码仓库只放程序不放数据。公开仓库里永远不要提交密钥、Database ID 等任何敏感信息（仓库里只放占位值）；部署示例里的域名都是占位示例。

**Q：想搬家怎么办？**
A：后台一键导出 Markdown 逃生包（文章原文 + 附件清单）或整站 JSON；图片视频本体在你的媒体桶里可整桶下载。天要下雨站要搬家，数据随时能走。

**Q：示例文章、示例说说怎么删？**
A：后台文章列表里删除即可（进回收站，30 天内可还原）；说说在「说说管理」里删。

## 隐私说明

- **访客侧**：本站不接任何第三方统计、不种广告 Cookie。评论者填的联系方式只存哈希与掩码，不明文落库；评论者 IP 只存加盐哈希，用于限流与防刷，不存明文 IP、不做画像。
- **浏览计数**：只有「哪篇文章哪天被看了几次」的聚合数字，没有访客级记录。
- **站长侧**：密码只存哈希 + 服务端胡椒；会话令牌只存哈希；恢复码只存哈希。真秘密（R2 密钥、任务密钥、胡椒）只存在 Cloudflare 环境变量里，**不进仓库、不进数据库**。
- **部署者注意**：Fork 后先把 `wrangler.toml` 里的示例值换成你自己的；仓库里出现的域名（`blog.example.com`、`media.example.com`）全是占位示例，不是任何人的真实站点。

## 已知边界（诚实清单）

- **SSRF 防护不查 DNS 解析结果（口径说明）**：友链探活与 AI 上游调用的防内网校验只看域名/IP 字面与跳转链，不做 DNS 解析后复检——一个公开域名若被解析到内网地址（DNS 重绑定），这一层拦不住，这是 Workers 平台限制下的已声明范围外项；AI 调用另已收紧为仅 https、默认端口、跨源跳转剥离 Key。
- **回收站里的媒体在真删前仍可凭原 URL 直取（公开桶固有形态）**：媒体桶绑了公开域名才能让访客看图，文件移入回收站只是数据库标记，对象本体要等保留期到期（或手动彻底删除）才真删，这期间知道原链接的人仍能打开；介意的话在回收站里直接用「彻底删除」。
- **Passkey（通行密钥 / 指纹登录）只是预留**：数据库表和接口路径已留好，本版返回「未启用」，登录仍以账密 + 恢复码为准。将来启用后可绕开慢哈希问题，是计划中的正解，但现在别指望它。
- **分片上传（Multipart）未做**：接口位已留、调用返回「未启用」。200MB 以内的视频走普通直传没问题；更大的文件请贴 B 站/YouTube 外链，或先压缩再传。
- **友链朋友圈抓取默认关且未实现聚合**：友链探活（查对方站点通不通）是真功能；「把友链最新文章抓过来聚合展示」只有开关和缓存表，抓取逻辑未做，开了也不会有数据，别开。
- **文章密码的哈希强度与登录同级**：为照顾免费版函数的算力上限用了折中参数；文章密码只当「熟人之间的小锁」，别拿它保护高敏感内容。
- **OG 分享元信息只到封面为止**：文章页带 og:title / og:description（后台「自动生成分享图元信息（OG）」开关控制，默认开），og:image 用文章封面、没设封面就没有；不逐篇自动生成大图，分享卡片显示以各平台抓取为准。
- **缩略图未接 Cloudflare 图片变换**：列表与封面用原图 + CSS 裁切显示，图特别多时首屏会稍重；这是可选项优化，未做不影响使用。
- **备份通道二（逐表导出的整库 SQL）是整库级恢复手段**：日常恢复优先用站内导入（按表 JSON）；整库 SQL 恢复步骤在维修手册里（产物文件头也写了恢复法），操作前先备份现状。
- **全文索引与官方整库导出互斥（平台限制），通道二已绕开**：自 v1.1.0 起库里有 FTS5 虚拟表，Cloudflare 官方整库导出会被服务端永久拒绝（cannot export databases with virtual tables）；通道二自 v1.1.3 起固定改走逐表 SQL 导出——结构解析自仓库 `schema/` 迁移文件（经 D1 HTTP API 自省表结构会被引擎授权器以 SQLITE_AUTH 拒绝，所以不向库问结构），数据逐表拼成整库 SQL 存 GitHub 90 天，恢复时执行产物 SQL 即可、文件末尾自带 FTS rebuild。通道一按表备份不含可重建的索引表，恢复后同样靠 rebuild 重建索引。**双通道均为真备份，不再有降级跳过**（始末见版本历史 v1.1.3）。**注意（v1.2.0 起）**：通道二产物在公开仓库里是任何登录用户可下载的 artifact，自 v1.2.0 起凭据与运行态表（admin_users / sessions / recovery_codes / login_guards / rate_limits / preview_tokens / autosaves / backups）只出结构不出数据，恢复后站长走首次初始化重建；Fork 使用者若把仓库设为公开，请同样留意自己更早版本产物的可见范围。
- **AI 写作只做管道**：本站不内置任何 AI 账号与额度，要用得自备 OpenAI 兼容服务的 Key；没配就等于没这功能，不影响其他任何功能。另外按口径，AI 的 Key 不进任何备份/导出产物（通道一备份、整站 JSON、Markdown 逃生包、通道二整库 SQL 全剔除），恢复站点后到后台「AI 写作」重填一次即可；老备份里带 Key 的仍可正常导入恢复。
- **第二层恢复（任务密钥开改密窗口）未实现**：忘密码时用第一层（恢复码）或第三层（终极重置），两层都在维修手册里写了全步骤。
- **仓库里的 wrangler.toml 是占位示例，不是真配置**：`database_id` 全零、`MEDIA_PUBLIC_BASE` 与 S3 端点都是示例值，部署时必须换成你自己的（方式一由流水线替换、方式二/三手动换）；没换就部署，站点会在备份/传图/查库时才报错，不会在启动时拦你，部署后请按「上线后自查清单」逐项验。
- **静态资源靠根目录 `_routes.json` 直出，别删**：`/assets/*`（前台样式与脚本）与 `/admin/*`（后台三件套）是纯静态文件，靠 `_routes.json` 把它们排除出函数调用、由 Pages 静态层直出；其余路径（含全部 `/api/*` 与页面 SSR）仍走函数。这个文件必须躺在部署根目录并随部署包一起上线——删了它、或部署时没带上它，首页还能开（函数 SSR 正常），但样式、脚本和整个后台页面会全部 404。排查口诀见维修手册故障对照表。
## 优点 · 缺点 · 与同类不同 · 已知问题速览

### 优点

- 功能齐全的个人博客：文章 + 说说（短动态）双形态，还有自带评论、搜索、订阅，不用拼凑第三方服务。
- 后台手机优先：发文、发图、改设置在手机上就能完成，还能定时发布。
- 备份是自动的：数据库定期自动导出备份，另有导入导出通道，数据永远在自己手里。
- 发图发视频直传存储桶，不经服务器中转，速度快还省额度。

### 缺点 / 要花钱的地方

- 本身 0 元，跑在 Cloudflare 免费额度上（数据库、存储、请求都有免费量）；花钱的只有自备域名（可选）。
- 功能多，代价是部署步骤比单文件小工具多：数据库、存储桶、环境变量都要建一遍，第一次上手要有点耐心。

### 和同类有什么不同

- 很多跑在 Cloudflare 上的博客只有文章功能；这个把「说说」做成了一等公民，日常小更新发说说、长内容写文章，分工明确。
- 为「一个人用手机维护」而设计：自动备份、自动巡检、看门狗式的自检流程都是标配，部署完不用惦记运维。

### 已知问题 / 注意事项

- 免费额度有上限：数据库读写、存储容量、每日请求量都是免费档的量，个人博客足够用；图片视频传太多会先撞到存储免费上限（10 GB 级别）。
- 备份类自动任务走 GitHub 的定时调度，偶尔会比预定时间晚一些，属平台常态，不影响博客本身访问。
- 首次初始化（设置站长账号）要在部署后尽快做完，不要把没初始化的站点长时间挂在公网上。

### v1.2.10（2026-11-26）· 全量复审 5 个疑似项逐条核实后修

- **解锁限流只数失败（S1）**：文章密码解锁以前在验密码之前就计数、输对了也占额度，正常读者连开 5 篇密码文就被锁 15 分钟。改成与登录同口径——先看存量、只给猜错计数；防爆破不变（猜错 5 次照样锁），成功解锁不再误伤。
- **自动封面精确匹配（S2）**：正文首图自动设封面以前只拿文件名做模糊匹配，外站图片和自家文件同名时会误认。现在按完整存储键精确查，只有自家媒体才会被认成封面。
- **退出登录补 CSRF 校验（S3）**：与本站其他写接口同口径，前端本来就带这个头，无感知。
- **响应体上限补实（S4）**：安全抓取以前只看对方声明的长度，没声明长度的分块响应能绕过上限。现在读取时逐块累计字节、超限立即断开，AI 接口的大响应同样受这道闸管。
- **防猜账号的假哈希换同轨（S5）**：登录时账号不存在也会跑一次假校验防靠快慢猜账号，假哈希以前是旧算法、与真实账号耗时不等价；换成与真实账号相同的主轨算法与参数，快慢不再露馅。

- **通道二为什么自上线起从未产出（三段根因，逐个实测钉死）**：① `wrangler.toml` 里的数据库 ID 一直是占位值，工作流识别到占位便静默跳过，从未真跑——这是它「看起来在备份、其实从没备份过」的直接原因；② 就算把 ID 填成真值，官方 `wrangler d1 export` 对含 FTS5 虚拟表的库会被平台**永久**拒绝（Cloudflare 官方 Known limitations 明列：含虚拟表的库不支持导出，变通只有删表，对生产库不可接受），且 wrangler 对只给 D1 读权限的令牌过不了它自己的鉴权（2026-11-10 实测 Authentication error code 10000）；③ 改走 D1 HTTP API 逐表导出后，第一句查表结构的 `SELECT … FROM sqlite_master`（`PRAGMA table_info` 同属此类）被 D1 引擎授权器以 `SQLITE_AUTH` 拒绝——两把权限完全不同的令牌撞出逐字相同的错，证明与令牌无关、是语句级限制（Cloudflare 社区 2026-10 有同案报告）。
- **最终路线（已生产跑通）**：`backup.yml` 通道二固定走新增的 `scripts/d1-dump.mjs` 逐表导出——结构解析自仓库 `schema/` 迁移文件（迁移是建库的唯一来源，结构上不会漂移；解析不了的语句直接报错终止、绝不静默漏表；每张非空表导出前先探一行核对列集，迁移之外的手工改列当场点名），数据经 D1 HTTP API 以显式列名逐表拼成整库 SQL，FTS 只出建表语句、产物末尾自带 rebuild；令牌换成专用只读的 `D1_EXPORT_TOKEN`（`Account · D1 · Read`，与部署令牌分开，仓库 Secrets 由 11 项变 12 项）。另把两个 job 改为串行：首跑时两 job 并行，官方导出尝试占用 D1 的窗口里通道一的站内备份吃了一次 500（导出期间会阻塞该库其他请求，平台已知限制），串行后互不干扰、通道一失败时通道二照常跑，通道一调用另加自动重试。
- **账面小修**：备份登记的 `size_bytes` 此前记的是 JSON 字符串长度而非真字节数（中文内容下约差一倍），自动/手动备份与导入前自动备份两处登记已统一改为 UTF-8 字节数；冒烟新增 1 项断言（登记值须与桶内对象字节数一致），共 167 项全过。
- **升级方法**：同步 `.github/workflows/backup.yml` 与新增的 `scripts/d1-dump.mjs`，在 Cloudflare 后台建一枚自定义令牌（`Account · D1 · Read`）存为仓库 Secret `D1_EXPORT_TOKEN`，再手动触发一次 backup，看到双 job 全绿、产物 `d1-export` 出现即成；站内代码除 size_bytes 修正外无行为变化。2026-11-10 本站生产实测：通道一新登记一期（23 篇文章 / 110 附件 / 56 评论 / 7 动态），通道二首份真产物落地（21 张表共 974 行，SQL 约 5.9 MB）。

## Fork 部署与原站的区别

代码与原站一模一样，但博客里的文章、图片、账号和自动化，全在作者自己的 Cloudflare 账号里；Fork 只能把代码带走，带不走作者的数据和配好的服务。差多少、怎么补，一条一条列清楚：

1. **文章不在仓库里，Fork 后是空博客**：全部文章、评论、说说和站点配置都存在作者自己的 D1 数据库 `ym-blog-db` 里，仓库里只有建表脚本 `schema/0001_init.sql`。按部署步骤跑完种子脚本 `schema/0002_seed.sql`，站里也只有 1 篇示例文章（另有 1 篇关于页、1 条示例说说，检查清单里本来就要求删掉），作者的文章一篇也不会跟着 Fork 走；想有内容，只能自己写。

2. **管理员账号密码要自己设**：仓库和部署里没有作者的管理员账号密码；首次打开自己站的 `/admin`，按提示设一个用户名和至少 8 位的密码，系统会给 10 个一次性恢复码，只显示一次，务必保存好。不要用 `INITIAL_ADMIN_PASSWORD` 环境变量预设管理员密码（这是高危做法，首次登录后必须清理）。

3. **媒体文件在作者的 R2 里**：文章里的图片、视频存在作者自己的 R2 存储桶（媒体桶 `ym-blog-media`，存储桶绑了自定义域名；备份桶 `ym-blog-backups`），不在仓库里。Fork 后要自己建桶、绑域名，再按部署步骤配好；原站的图片、视频一张也不会出现在你的站里。

4. **AI 写作要填自己的密钥**：AI 写作助手可选、自备 Key，接任意 OpenAI 兼容服务（OpenAI / DeepSeek / 各类中转），在自己站后台「站点设置 → AI 写作」里填服务地址、API Key、模型、温度和两套提示词；不填就没有这个功能。密钥只存服务端，页面只显示是否已配置，永远不下发。

5. **自动化要自己配**：部署、看门狗、友链探活、每日清理、每周备份、心跳保活这些工作流都在 `.github/workflows/` 里，代码会跟着 Fork 走，但 GitHub 的安全规则让它们不能直接用：Fork 后 Actions 默认是关闭的，定时任务默认不跑；13 个 GitHub Secrets（`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`、`D1_DATABASE_ID`、`D1_EXPORT_TOKEN`、`BACKUP_PASSPHRASE`、`MEDIA_PUBLIC_BASE`、`R2_S3_ENDPOINT`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`、`PASSWORD_PEPPER`、`TASK_SECRET`、`INITIAL_ADMIN_USERNAME`、`SITE_URL`）不会跟着 Fork 复制。补齐办法：去自己仓库的 Actions 页手动启用一次工作流，再按「配置表」把 13 个 Secrets 和 Cloudflare 侧的 D1 / R2 / Pages 绑定配好；看门狗和友链探活还要在自己站里填好 `SITE_URL` 与 `TASK_SECRET` 才能跑起来。

6. **代码里的功能，Fork 后全都有**：Markdown 编辑 + 实时预览、三层防丢稿、文章状态机与回收站（30 天）、历史版本（最近 20 版）、全文搜索（FTS5 + trigram）、深色模式三段式、6 套预设配色（活力橙 / 海洋蓝 / 葡萄紫 / 森系绿 / 湖水青 / 玫红）、媒体库与媒体回收站、评论先审后显与防刷、友链探活、说说、归档 / 标签 / 关于页——这些全在代码里，部署好即有，不用另配。

补齐「自己的 D1 + R2 + 13 个 Secrets + 手动启用一次 Actions」后，你的站和原站在功能上完全一致；差别只剩内容：文章、图片、评论和日常巡检，都是你自己的了。原站的文章和媒体、作者的 Cloudflare 账号与域名绑定，永远无法复制——这是设计使然：数据只能存在自己的账号里。

**Q：Fork 后直接部署就能用吗？**

A：能打开、能注册管理员、能写文章，但站里没有作者的文章和图片，自动化也没启用；先按「部署方法」走完（含第 9 步的 6 项自查清单），再把 Secrets 和 Actions 配好，才算真正可用。

**Q：能把原站的文章搬到我的 Fork 站上吗？**

A：不能一键搬。文章在作者的 D1 里，不在仓库里，也没有现成的导出文件跟着 Fork 走；只能一篇篇自己复制重发，图片要重新传进自己的 R2。

**Q：为什么 Fork 后 Actions 不自动跑？**

A：这是 GitHub 的安全规则：Fork 的仓库里 Actions 默认关闭，定时任务默认不跑，Secrets 也不复制——防止别人 Fork 一个仓库就能用原作者的密钥和额度。所以必须先手动启用一次工作流，补齐自己的 Secrets，它才会按定时自动跑。
